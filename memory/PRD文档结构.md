## PRD 文档结构

### 三层结构

```
总 PRD（轻量，定方向 + 模块清单 + 模块间依赖）
  │
  ├── 模块 A PRD（数据模型 + 业务规则 + 状态机 + 权限 + 路由）
  │   ├── 页面-列表页 PRD（列定义、筛选、排序、分页、批量操作）
  │   ├── 页面-新增编辑 PRD（表单字段、校验规则、提交逻辑）
  │   └── 页面-详情页 PRD（信息展示、操作按钮、关联数据）
  │
  └── 模块 B PRD（同上结构）
```

### 核心原则

- **共享信息上提到模块主 PRD**：数据模型、业务规则、状态机、权限定义只写一次
- **页面 PRD 只描述该页面**：6 个必须回答的问题：
  1. 有哪些状态？（加载/空/错误/正常/无权限）
  2. 每个状态下显示什么？
  3. 用户可做什么操作？
  4. 操作后发生什么？
  5. 数据从哪来、往哪去？
  6. 有哪些边界情况？

### 文件命名规范

```
教室管理/
├── 教室管理主PRD.md
├── 教室管理-列表页.md
├── 教室管理-新增编辑.md
└── 教室管理-详情页.md
```

**Why:** AI 拿到页面 PRD + 主 PRD 的数据模型/权限定义后无需猜测，可直接实现。跨页面共享信息不重复，避免不一致。
**How to apply:** 每个新模块开始开发前，先按此结构完成 PRD 文档。
