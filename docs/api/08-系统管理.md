## 1. 参数配置 — SysConfigController

**Base Path**：`/api/v1/system/config`

| # | 方法 | 路径 | 说明 | 权限 |
|:--|:----|------|------|------|
| 1 | `GET` | `/list?page=&pageSize=&keyword=&configType=&sysBuiltIn` | 分页列表 | `system:config:list` |
| 2 | `GET` | `/{configId}` | 配置详情 | `system:config:query` |
| 3 | `GET` | `/configKey/{configKey}` | 按键名查值（公开） | — |
| 4 | `POST` | `/` | 新增配置 | `system:config:add` |
| 5 | `PUT` | `/` | 编辑配置 | `system:config:edit` |
| 6 | `DELETE` | `/{configIds}` | 批量删除 | `system:config:delete` |
| 7 | `POST` | `/refreshCache` | 刷新缓存 | `system:config:edit` |

### 1.1 分页列表

```
GET /api/v1/system/config/list?page=1&pageSize=10&keyword=系统&configType=Y&sysBuiltIn=Y
```

**Query 参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `page` | long | — | 页码，默认 1 |
| `pageSize` | long | — | 每页条数，默认 10 |
| `keyword` | string | — | 模糊搜索（匹配配置名称） |
| `configType` | string | — | 配置类型过滤（对应 key 字段） |
| `sysBuiltIn` | string | — | 是否内置（对应 type 字段，Y/N） |

**响应**：`PageResult<SysConfig>`

### 1.2 按键名查值

```
GET /api/v1/system/config/configKey/{configKey}
```

无需权限，用于前端获取公开配置（如站点名称、Logo URL 等）。返回 `String` 类型的配置值。

| # | 方法 | 路径 | 说明 | 权限 |

| 7 | `DELETE` | `/{dictIds}` | 批量删除 | `system:dict:delete` |

### 2.1 分页列表

```
GET /api/v1/system/dict/type/list?page=1&pageSize=10&keyword=性别&status=0
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `keyword` | string | — | 模糊搜索（匹配字典名称） |
| `status` | int | — | 状态过滤（0=正常） |

```
POST /api/v1/system/dict/type/cache/refresh
```

当前后端无服务端字典缓存（每次查询直接走 DB），此端点供前端调用以清空前端的 Pinia Store 字典缓存。

## 3. 字典数据 — SysDictDataController

**Base Path**：`/api/v1/system/dict/data`

| # | 方法 | 路径 | 说明 | 权限 |
|:--|:----|------|------|------|
| 1 | `GET` | `/type/{dictType}` | 按类型查数据（如性别下拉） | `system:dict:query` |
| 2 | `GET` | `/list?page=&pageSize=&keyword=&typeCode=&status` | 分页列表 | `system:dict:list` |
| 3 | `GET` | `/all` | 全部数据分组返回（公开） | — |
| 4 | `GET` | `/{dictCode}` | 字典数据详情 | `system:dict:query` |
| 5 | `POST` | `/` | 新增字典数据 | `system:dict:add` |
| 6 | `PUT` | `/` | 编辑字典数据 | `system:dict:edit` |
| 7 | `DELETE` | `/{dictCodes}` | 批量删除 | `system:dict:delete` |

### 3.1 按类型查数据

```
GET /api/v1/system/dict/data/type/sys_user_sex
```

返回 `List<SysDictData>`，用于下拉框。

### 3.2 全部数据分组

```
GET /api/v1/system/dict/data/all
```

返回 `Map<String, List<SysDictData>>`，按 `typeCode` 分组。无需权限，供前端初始化时批量加载字典。

### 3.3 分页列表

```
GET /api/v1/system/dict/data/list?page=1&pageSize=10&typeCode=sys_user_sex&status=0
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `keyword` | string | — | 模糊搜索（匹配 label） |
| `typeCode` | string | — | 字典类型编码过滤 |
| `status` | int | — | 状态过滤 |

## 5. 通知公告 — SysNoticeController

**Base Path**：`/api/v1/system/notice`

| # | 方法 | 路径 | 说明 | 权限 |
|:--|:----|------|------|------|
| 1 | `GET` | `/list?page=&pageSize=&keyword=&type=&status` | 分页列表 | `system:notice:list` |
| 2 | `GET` | `/{noticeId}` | 公告详情 | `system:notice:query` |
| 3 | `POST` | `/` | 新增公告 | `system:notice:add` |
| 4 | `PUT` | `/` | 编辑公告 | `system:notice:edit` |
| 5 | `DELETE` | `/{noticeIds}` | 批量删除 | `system:notice:delete` |

### 5.1 新增/编辑的特殊逻辑

- 新增时若 `status=1`（直接发布），自动设置 `publishBy`（当前用户）和 `publishTime`
- 编辑时若 `status` 从 `0`（草稿）变为 `1`（发布），自动设置发布人和发布时间
- `createBy` / `updateBy` 由后端自动填充当前用户 ID

### 5.2 分页列表

```
GET /api/v1/system/notice/list?page=1&pageSize=10&keyword=通知&type=1&status=0
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `keyword` | string | — | 模糊搜索（匹配标题） |
| `type` | string | — | 公告类型（1=通知, 2=公告） |
| `status` | int | — | 状态（0=正常, 1=草稿, 2=关闭） |
