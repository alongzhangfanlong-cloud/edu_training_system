# M3 学员管理

> **模块定位**：基础资源层（P0），高频使用的独立顶层菜单。维护学生档案、家长关联信息，提供课时变动流水和报班记录的只读查询。
> **路由**：`/student`
> **权限码前缀**：`student:*`
> **后端模块**：`edu-module-student`

---

## 1. 页面清单

| 序号 | 路由 | 页面 | 说明 |
|:--:|------|------|------|
| 1 | `/student` | 学员列表页 | 搜索 + 筛选 + 表格 + 新增/编辑弹窗 |
| 2 | `/student/:id/enrollments` | 报班记录页（也可抽屉） | 该学生所有报班列表 |
| 3 | — | 课时记录抽屉 | 行内按钮触发，右侧 Drawer |
| 4 | — | 新增/编辑学员弹窗 | 工具栏或行内触发，含家长子表格 |

> **注意**：报班记录可采用 Drawer 或独立子页面（`/student/:id/enrollments`），最终由前端开发时确定。本文档以 Drawer 为主要方案描述。

### 2.2 搜索栏

| 字段 | 类型 | 默认值 | 说明 |
|------|------|------|------|
| 关键词 | 文本输入 | 空 | 模糊匹配姓名 / 手机号 / 学校 |
| 年级 | 下拉单选 | 全部 | 小学一年级 ~ 高中三年级 + "学前" + "其他"，见 §8.1 年级枚举 |
| 状态 | 下拉单选 | 全部 | 全部 / 在读 / 停课 / 结课 / 流失 |

**按钮**：

| 按钮 | 行为 |
|------|------|
| 搜索 | 重置到第 1 页 → 调用 `GET /api/v1/student/list` |
| 重置 | 清空搜索条件 → 重新加载 |

**竞态保护**：搜索按钮触发，使用竞态序号模式（见前端规范 `CLAUDE_front.md` 模式二）。

### 2.3 工具栏

| 按钮 | 权限码 | 说明 |
|------|--------|------|
| + 新增学员 | `student:add` | 打开新增弹窗（§4） |
| 导入 | `student:import` | 打开导入弹窗（§2.8） |
| 导出 | `student:export` | 以当前搜索条件导出全部匹配数据（不分页），浏览器下载 Excel |

> 学员管理不提供「批量删除」按钮，删除操作限制在行内逐个操作，避免误删。

### 2.4 数据表格

#### 2.4.1 列定义

| 列 | 宽度 | 对齐 | 说明 |
|------|:--:|:--:|------|
| 序号 | 60px | 中 | 自动编号（分页连续） |
| 姓名 | 100px | 左 | `name`，空则显示"--" |
| 性别 | 60px | 中 | 男 / 女 |
| 年级 | 90px | 中 | `grade` 的中文名称 |
| 学校 | 140px | 左 | `school`，可空（显示"--"） |
| 手机号 | 130px | 左 | 脱敏：`138****5678` |
| 状态 | 90px | 中 | 见 §2.4.2 状态标签 |
| 报班数 | 70px | 中 | 在读班级数量，点数字可跳转报班记录（如果≥1） |
| 剩余课时 | 90px | 中 | 所有在读班级剩余课时之和，含赠送课时 |
| 最近到校 | 120px | 左 | `YYYY-MM-DD`，取自最近签到记录的签到日期，无记录显示"--" |
| 操作 | 220px | 中 | 按钮组（见 §2.5） |

#### 2.4.2 状态标签

| 状态值 | 标签颜色 | 文案 | 说明 |
|------|:--:|------|------|
| `enrolled` | green | 在读 | 正常在读学员 |
| `suspended` | orange | 停课 | 暂停上课，剩余课时保留 |
| `completed` | blue | 结课 | 所有课程已结课，课时耗尽 |
| `lost` | red | 流失 | 长期未到校、主动退学等 |

#### 2.4.3 排序

默认按 `create_time DESC` 排序。支持点击「最近到校」列头排序（升/降切换）。

#### 2.4.4 手机号脱敏

前端统一处理：`mobile.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2')`。导出时是否脱敏待确认（建议导出时显示完整手机号，权限由后端控制）。

### 2.5 操作列按钮

| 按钮 | 权限码 | 行为 |
|------|--------|------|
| 详情 | `student:view` | 打开编辑弹窗（只读模式）或跳转详情页——由前端确定。MVP 阶段复用编辑弹窗，所有字段 `disabled` |
| 报班记录 | `student:view` | 打开报班记录抽屉（§6） |
| 课时记录 | `student:view` | 打开课时记录抽屉（§5） |
| 编辑 | `student:edit` | 打开编辑弹窗（数据预填） |
| 删除 | `student:delete` | 二次确认 → 调用 API。仅当该学员无在读班级、无未消耗课时时允许删除 |

### 2.6 删除保护规则

删除前前端校验（后端同时校验）：

| 条件 | 行为 |
|------|------|
| 有在读班级（报班记录状态=在读） | 禁止删除："该学员还有 {N} 个在读班级，请先办理退班/结课后再删除" |
| 有剩余课时（>0） | 禁止删除："该学员还有 {N} 课时未消耗，请先办理退费后再删除" |
| 无在读班级且无剩余课时 | 二次确认："确认删除学员「{姓名}」？删除后不可恢复。关联的家长信息、课时变动记录将保留。" |

> **重要**：删除学员时不级联删除家长 sys_user（可能关联其他学生），不删除课时变动记录（财务审计需求）。学员记录本身使用逻辑删除 `is_deleted`。

### 2.7 分页器

| 元素 | 说明 |
|------|------|
| 页码 | 标准页码按钮，当前页高亮 |
| 每页条数 | 下拉选择：10 / 20 / 50 / 100，默认 20 |
| 总条数 | "共 {total} 条" |
| 跳转 | 「前往」输入框 + 确认 |

### 2.8 导入

流程：

1. 点击「下载模板」→ `GET /api/v1/student/template` → 浏览器下载 Excel
2. 点击「导入」→ 打开导入弹窗（上传区域 + 下载模板链接）
3. 上传文件 → 文件格式校验（仅允许 `.xlsx` `.xls`，最大 10MB）→ 调 `POST /api/v1/student/import`
4. 返回结果 → 弹窗展示导入结果（成功/失败列表）

### 2.9 导出

点击「导出」→ 将当前搜索条件（不分页）调 `GET /api/v1/student/export` → 浏览器下载 Excel。

导出列：姓名、性别、年级、学校、手机号（完整号码）、状态、报班数、剩余课时、最近到校日期。

## 3. 新增/编辑学员弹窗

### 3.1 触发

- 新增：工具栏「+ 新增学员」
- 编辑：操作列「编辑」
- 详情：操作列「详情」（所有字段只读 + 无提交按钮，标题改为「学员详情」）

### 3.2 弹窗规格

- 宽度：700px（含家长子表格，较标准弹窗更宽）
- 高度：自适应，最大 80vh 内部滚动
- 标题：「新增学员」/「编辑学员」/「学员详情」

### 3.3 基本字段

| 字段 | 类型 | 必填 | 新增时 | 编辑时 | 校验规则 |
|------|------|:--:|:--:|:--:|------|
| 姓名 | 文本 | ✅ | 显示 | 显示 | 1-20 字符 |
| 性别 | 单选组 | ✅ | 显示 | 显示 | 男 / 女 |
| 年级 | 下拉单选 | ✅ | 显示 | 显示 | 见 §8.1 年级枚举 |
| 学校 | 文本 | ❌ | 显示 | 显示 | 0-50 字符 |
| 手机号 | 文本 | ✅ | 显示 | 显示 | 11 位数字，1 开头。失焦异步校验唯一性（编辑时排除自身）。见 §8.2 |
| 标签 | 标签输入 | ❌ | 显示 | 显示 | 自由输入 + 回车添加，最多 5 个标签，每标签最长 10 字符 |
| 状态 | 下拉单选 | — | **不显示** | 显示 | 仅编辑时显示，可选：在读 / 停课 / 结课 / 流失。新增默认=在读 |

> **新增时状态不显示**：新增学员默认状态为「在读」，无需用户选择。

### 3.4 家长子表格

家长信息在新增/编辑学员的同一弹窗中，以子表格形式维护。

#### 3.4.2 添加/编辑家长行内编辑

点击「+ 添加家长」→ 在子表格顶部新增一行内联编辑行：

```
┌─────────┬──────────┬──────────┬──────────┬──────────┐
│         │ [____]   │ [▾选择]  │ [____]   │ ✓确定 ✕取消│
└─────────┴──────────┴──────────┴──────────┴──────────┘
```

| 字段 | 类型 | 必填 | 校验 |
|------|------|:--:|------|
| 姓名 | 文本 | ✅ | 1-20 字符 |
| 关系 | 下拉单选 | ✅ | 父亲 / 母亲 / 爷爷 / 奶奶 / 外公 / 外婆 / 其他 |
| 手机号 | 文本 | ✅ | 11 位数字，1 开头。同一学员下家长手机号不可重复（红字提示） |

点击编辑某一行 → 该行切换为内联编辑模式（同上）。点击 ✓ 确认 → 行回到展示模式。点击 ✕ 取消 → 丢弃修改。

#### 3.4.3 家长保存时机

家长信息与学生信息**在同一弹窗中、同一提交按钮**一起保存。不存在"先保存学生再单独添加家长"的流程。

整个弹窗的提交流程（见 §3.6）包含：
1. 保存/更新学生信息
2. 保存/更新/删除家长信息（前端 diff 后传输变更集）
3. 按手机号检查/自动创建家长 sys_user 账号

#### 3.4.4 删除家长校验

删除前检查：该家长手机号是否还关联同学生的其他家长记录？若仅此一条：
- 软提示："删除后该家长将无法通过小程序登录查看此学生的信息。"
- 不阻止删除。

> 家长 sys_user 不删除（可能关联其他学生），仅解除与该学生的关联。

### 3.5 编辑提交时的家长变更集

前端维护家长列表的增删改标记，提交时传输：

```json
{
  "id": 1,
  "name": "张三",
  "gender": "M",
  "grade": "GRADE_5",
  "school": "育才小学",
  "mobile": "13800001111",
  "tags": ["数学培优", "竞赛"],
  
  "parentChanges": {
    "added": [
      { "name": "张母", "relation": "MOTHER", "mobile": "13900001111" }
    ],
    "updated": [
      { "id": 10, "name": "张父(更新)", "relation": "FATHER", "mobile": "13800002222" }
    ],
    "removed": [11]
  }
}
```

> 后端在事务内依次处理学生更新 + 家长增删改 + sys_user 关联检查。任何一个步骤失败则整体回滚。

### 3.6 交互

| 操作 | 行为 |
|------|------|
| 打开（新增） | 空表单，默认性别"男"，年级默认"小学一年级"，家长子表格为空 |
| 打开（编辑） | 调用 `GET /api/v1/student/{id}` → 填充表单 + 加载家长列表 |
| 打开（详情） | 同编辑，但所有字段 disabled + 无底部按钮（仅「关闭」） |
| 确认 | 前端校验 → 提交 API（见 §3.4）→ 成功 → toast + 关闭弹窗 + 刷新列表 |
| 取消 | 有修改 → 确认"放弃修改？"；无修改 → 直接关闭 |

### 3.7 状态处理

| 状态 | 表现 |
|------|------|
| 加载中（编辑/详情） | 弹窗内骨架屏（学生区 + 家长区各一个灰色块） |
| 加载失败（编辑/详情） | "加载学员信息失败" + 「重试」 |
| 手机号唯一性校验中 | 输入框右侧 loading 图标 |
| 手机号已被占用 | 红色错误"该手机号已被其他学员使用"，不可提交 |
| 提交中 | 确认按钮 loading，"保存中…" |
| 提交失败 | 保留弹窗 + 错误提示（后端返回的 msg） |
| 提交成功 | toast "保存成功" + 关闭弹窗 + 刷新列表 |

### 3.8 对应 API

| 操作 | API |
|------|------|
| 新增 | `POST /api/v1/student` |
| 编辑 | `PUT /api/v1/student/{id}` |
| 详情 | `GET /api/v1/student/{id}` |

## 8. 业务规则

### 8.1 年级枚举

```
学前, 小学一年级, 小学二年级, 小学三年级, 小学四年级, 小学五年级, 小学六年级,
初中一年级, 初中二年级, 初中三年级,
高中一年级, 高中二年级, 高中三年级,
其他
```

后端存储为 `VARCHAR(20)` 代码（如 `PRESCHOOL`, `GRADE_1`, `GRADE_7`, `GRADE_10`），前端展示中文。

### 8.2 手机号唯一性规则

- **学生手机号**：全局唯一（软唯一，即 `is_deleted=0` 的记录中不可重复）。新增时校验，编辑时排除自身后校验。
- **家长手机号**：同一学生下不可重复（同一手机号可关联不同学生）。
- **校验时机**：失焦时异步调用后端校验。
- **硬阻断**：手机号已被占用 → 红色错误提示，不可保存。

### 8.3 家长自动创建 sys_user

**触发时机**：学员保存时（新增或编辑），对于家长子表格中**新增或修改手机号**的家长记录。

**处理逻辑**：

```
foreach parent in (parentAdds + parentUpdates where mobile changed):
    user = sys_user 按 mobile 查询
    if user == null:
        创建 sys_user:
            username = mobile
            real_name = parent.name
            password = 随机 16 位字符串 (BCrypt 加密)
            role = "PARENT" (家长角色)
            status = 0 (正常)
    else if user.role 不含 PARENT:
        为该 user 追加 PARENT 角色
    // 如果 user 已存在且已有 PARENT 角色，不做任何操作
```

> **注意**：
> - 删除家长时不删除对应的 sys_user（该家长可能还关联其他学生）。
> - 修改家长手机号时，旧的 sys_user 关联不自动清理（需管理员手动处理或后续功能补充）。
> - 家长通过微信小程序首次登录时，`wx_openid` 绑定到对应的 sys_user。

### 8.4 学生状态流转规则

```
                    ┌──────────┐
          ┌────────>│  在读    │─────────┐
          │         │ enrolled │         │
          │         └─────┬────┘         │
          │               │              │
    ┌─────┴─────┐   ┌─────▼─────┐   ┌───▼──────┐
    │  停课     │   │  结课     │   │  流失    │
    │ suspended │   │ completed │   │  lost    │
    └─────┬─────┘   └───────────┘   └──────────┘
          │               ▲              │
          └───────────────┘              │
          (重新激活)                      │
                                         │
          ┌──────────────────────────────┘
          │  (重新报名后自动恢复在读)
```

| 从 | → 到 | 触发条件 | 手动/自动 |
|------|------|------|:--:|
| — | 在读 | 新增学员 / 重新报名 | 自动 |
| 在读 | 停课 | 管理员主动操作（如请假过长/暂停） | 手动 |
| 在读 | 结课 | 所有报班记录状态=已结课，且剩余课时=0 | 自动 |
| 在读 | 流失 | 管理员标记（连续 N 天未到校） | 手动(或配置自动) |
| 停课 | 在读 | 管理员恢复 | 手动 |
| 流失 | 在读 | 重新报名（产生新报班记录） | 自动 |

**状态联动规则**：
- 学生状态=「结课」或「流失」时，不可新增报班记录（报名模块需校验）。
- 学生状态从「结课」/「流失」变更为「在读」时，需有新的报班记录。

### 8.5 课时变动联动规则

| 上游操作 | 课时变动类型 | 数量计算 | 联动模块 |
|------|------|------|------|
| M7 收费确认 | 报名获得 | +(购买的课时数) | M7 → M3 |
| M7 赠课时审批 | 赠送获得 | +(赠送课时数) | M7 → M3 |
| M8 签到成功 | 上课消耗 | -(本次上课应扣课时) | M8 → M3 |
| M8 请假审批通过 | 请假返还 | +(已扣的课时) | M8 → M3 |
| M8 补课签到 | 补课消耗 | -(补课消耗课时) | M8 → M3 |
| M7 退费审批通过 | 退费扣回 | -(已退课时数) | M7 → M3 |

**课时变动记录不可编辑、不可删除**——所有数据由上游模块的业务操作触发写入。

> **后端约束**：`edu-module-student` 模块提供课时变动的写入 API（仅供内部模块间调用，不暴露为 Controller），由 M7 和 M8 等模块的 Service 层调用。

### 8.6 剩余课时汇总计算

学生「剩余课时」= 所有「在读」状态的报班记录中 `remaining_hours` 之和。

计算公式（后端执行，不依赖前端累加课时变动记录）：
```
SELECT SUM(remaining_hours) FROM edu_enrollment WHERE student_id = ? AND status = 'enrolled' AND is_deleted = 0
```

## 11. 异常边界

### 11.1 并发冲突

| 场景 | 处理策略 |
|------|------|
| 两人同时编辑同一学员 | 乐观锁或最后写入胜出。MVP 阶段采用"最后写入胜出"（不做版本冲突检测），提交时后端取最新数据更新。若后续高频出现冲突，再加 `version` 字段乐观锁。 |
| 同一家长手机号同时关联到不同学生 | 允许（不同学生可有相同手机号的家长），sys_user 可关联多个学生。 |
| 课时变动记录同时写入 | 数据库行锁 + 事务保证。`edu_student_hour_log` 只追加不修改，无并发冲突。 |

### 11.2 数据一致性

| 场景 | 处理策略 |
|------|------|
| 报名成功但课时变动记录写入失败 | 事务回滚。M7 收费确认 + 课时写入在同一事务中。 |
| 签到消耗课时后剩余课时变负数 | 不允许。签到前校验 `remaining_hours >= consume_amount`，不足则阻止签到并提示"课时不足，请先续费"。 |
| 删除学员时家长 sys_user 残留 | 不删除家长 sys_user。家长可能关联其他学生。`edu_student_parent` 使用逻辑删除。 |
| 退费金额大于剩余课时价值 | 业务规则：退费金额 = 剩余课时 × 课时单价。由 M7 模块校验，M3 模块提供当前剩余课时供计算。 |

### 11.3 边界输入

| 场景 | 处理策略 |
|------|------|
| 姓名过长（>20字符） | 前端 maxlength 限制 + 后端校验，返回"姓名最多 20 字符" |
| 手机号格式非法 | 前端正则 `^1\d{10}$` + 后端校验，返回"手机号格式不正确" |
| 家长子表格为空（提交时） | 允许保存，学生可以不关联家长 |
| 家长超过 5 个 | 前端不硬限制，但子表格支持分页。提示"建议关联不超过 5 位家长" |
| 标签超过 5 个 | 前端限制最多 5 个，input 在已有 5 个标签后禁用 |
| 标签超过 10 字符 | 前端 maxlength + 后端校验 |

### 11.4 权限边界

| 场景 | 处理 |
|------|------|
| 无 `student:view` 权限 | 左侧菜单不显示「学员管理」。直接访问 URL → 后端返回 403 → 前端跳转 403 页面 |
| 无 `student:add` 权限 | 隐藏「新增学员」按钮 |
| 无 `student:edit` 权限 | 隐藏「编辑」按钮，但不影响详情/报班记录/课时记录按钮（这些需要 `student:view`） |
| 无 `student:delete` 权限 | 隐藏「删除」按钮 |
| 教师角色 | 不需要 `student:view`，教师不操作学员管理菜单 |
| 家长角色 | 不需要 `student:view`，家长通过小程序查看自己关联学生的信息（通过家长端专用 API） |
