# M7 收银管理

> **模块定位**：消费 M6 报名管理的报名记录，完成收费确认、退费处理、赠送课时、财务对账。「招生管理」核心模块之一，聚焦资金流的全生命周期管理。
> **优先级**：P0，核心教务层
> **后端包**：`edu-module-tuition`
> **前端菜单**：招生管理 > 收费管理 / 退费处理 / 赠送课时 / 财务对账（与 M6 报名管理合并为「招生管理」顶层菜单）

---

## 1. 模块概述

### 1.1 业务背景

教育机构的收费场景呈现多样化特征：
- 同一学生可能同时购买多个课程包，分多次缴费
- 退费场景涉及课时扣回计算，需要有清晰的审批和追溯链路
- 运营促销活动中存在免费赠送课时的场景
- 校长/运营主管需要按日/周/月进行财务对账

M7 收银管理作为资金流的中枢模块，承接 M6 报名管理的待收费数据，联动 M3 学员管理的课时余额，为机构提供完整的收银闭环。

### 1.2 模块边界

| 在范围内 | 不在范围内（本期不做） |
|----------|------------------------|
| 收费确认（关联 M6 报名记录） | 在线支付通道接入 |
| 退费申请与审批流程 | 发票管理 |
| 赠送课时与记录 | 优惠券/折扣系统 |
| 收据凭证生成（前端） | 财务报表导出（高级） |
| 财务对账统计 | 与银行/第三方账单自动对账 |
| 费用类型管理（报名费/课时费/教材费/其他） | 多币种支持 |

### 1.3 与其他模块的关系

```
M6 报名管理 ──消费报名记录──→ M7 收银管理 ──写课时明细──→ M3 学员管理
                                    │
M0 系统管理 ──经手人(当前用户)──→ M7 收银管理
```

| 模块 | 关系 | 数据流向 |
|------|------|------|
| M6 报名管理 | 消费方 | M7 读取 M6 的报名记录，生成待收费条目；收费后回写 M6 报名记录的收费状态 |
| M3 学员管理 | 写入方 | 收费确认 → 写入学员课时明细（获得）；退费通过 → 写入学员课时明细（扣回）；赠送课时 → 写入学员课时明细（赠送获得） |
| M0 系统管理 | 引用方 | 经手人取自当前登录用户 `sys_user`；审批人通过权限模型判断 |

#### 3.4.3 表单字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| 支付方式 | 下拉单选 | ✅ | 现金 / 微信 / 支付宝 / 银行转账 |
| 费用类型 | 下拉单选 | ✅ | 默认继承报名记录的费用类型，可修改 |
| 实缴金额 | 数字输入 | ✅ | 正整数或小数（最多两位），`0 < 实缴金额 ≤ 未缴金额` |
| 备注 | 文本域 | ❌ | 最多 200 字符 |

#### 3.4.4 课时入账预览

当报名记录关联的课程有单价信息时，弹窗下方实时计算并展示课时入账预览：

- **入账课时数** = 向下取整（实缴金额 / 课程单价）
- 如课程单价未设置或无课时概念（如纯报名费），则显示「本次收费不涉及课时入账」
- 如实缴金额不足以覆盖 1 课时（实缴金额 < 课程单价），显示警告 ⚠「本次缴费金额不足以覆盖 1 课时，将不触发课时入账」

#### 3.4.5 交互

| 操作 | 行为 |
|------|------|
| 打开 | 自动填充未缴金额为实缴金额（一键全额收费），加载课程单价信息 |
| 修改实缴金额 | 实时更新课时入账预览 |
| 确认收费 | 前端校验 → 调用 API → 成功 → toast「收费成功」 + 关闭弹窗 + 刷新列表 |
| 取消 | 有修改 → 确认"放弃本次收费？"；无修改 → 直接关闭 |

#### 3.4.6 状态

| 状态 | 表现 |
|------|------|
| 提交中 | 确认按钮 loading，「处理中…」 |
| 提交失败 | 保留弹窗 + 错误提示 |
| 课程信息加载中 | 课时入账预览区骨架屏 |
| 课程无单价 | 课时入账预览区显示「当前课程未设置课时单价，不触发课时入账」 |

#### 3.4.7 收费编号规则

格式：`T` + `YYYYMMDD` + `4位流水号`，例如 `T202607130001`

后端生成，全局唯一，用于收据凭证和财务对账引用。

## 4. 退费处理

> 路由：`/enroll/refund`
> 权限码：`tuition:refund:list`
> 操作权限：`tuition:refund:apply`（发起退费）、`tuition:refund:approve`（审批退费）、`tuition:refund:reject`（驳回退费）

### 4.1 核心流程

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  运营主管      │    │  系统判断      │    │  校长审批      │    │  系统执行      │
│  发起退费申请  │ →  │  是否需要审批  │ →  │  审批通过/驳回 │ →  │  课时扣回     │
│              │    │              │    │              │    │  退款记录     │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
                           │                                      │
                           │ 小额直退                               │
                           └──────────────────────────────────────┘
```

### 4.2 审批阈值规则

| 退费金额 | 审批流程 | 说明 |
|------|------|------|
| ≤ 审批阈值 | 无需审批，直接退费 | 运营主管提交后即时生效 |
| > 审批阈值 | 运营主管发起 → 校长审批 | 审批通过后执行退费；驳回则保留记录 |

**审批阈值**通过 M0 系统配置管理，配置项 `tuition.refund.approval_threshold`，默认值 `500.00`（元）。支持运营主管在系统配置中修改。

#### 4.8.4 课时扣回预览

实时计算并展示：

- **应扣课时数** = 向上取整（退费金额 / 课程单价）
- **剩余课时**：当前学生在该课程下的剩余课时
- **扣回后剩余** = 剩余课时 - 应扣课时数

**警告场景：**

| 情况 | 提示 |
|------|------|
| 扣回后剩余 ≥ 0 | 绿色 ✅ 正常 |
| 扣回后剩余 < 0 | 橙色 ⚠「该学生剩余课时不足扣回，扣回后课时余额为负数（{-N} 课时），请确认后再提交。」 |
| 课程无单价 | 灰色「该课程未设置课时单价，本次退费不涉及课时扣回」 |

#### 4.8.5 审批规则判断

提交退费申请时，系统根据退费金额和审批阈值自动判断：

- **退费金额 ≤ 审批阈值**：直接通过，状态 =「已完成」，课时扣回立即执行
- **退费金额 > 审批阈值**：状态 =「待审批」，等待校长审批

提交时弹窗下方显示审批路径提示：
- 小额：「本次退费金额未超过审批阈值（¥500.00），提交后将直接执行退费。」
- 大额：「本次退费金额超过审批阈值（¥500.00），提交后将进入审批流程，请等待校长审批。」

## 8. 业务规则

### 8.1 报名 → 收费 → 课时入账 完整流程

```
1. 运营主管在 M6 录入报名信息
   → 选择学生 + 课程/班级 + 费用信息 + 应缴金额 + 经手人
   → 生成报名记录（状态=待收费）
   → 该记录出现在 M7 收费管理「待收费」列表

2. 运营主管在 M7 确认收费
   → 选择支付方式 + 实缴金额（支持部分收费）
   → 系统生成收费记录 + 收费编号（T202607130001）
   → 回写 M6 报名记录的收费状态：
      实缴金额 < 应缴金额 → 「部分收费」
      实缴金额 = 应缴金额 → 「已收费」
   → 如有课程单价：
      入账课时数 = floor(实缴金额 / 课程单价)
      写入 M3 学员课时明细（类型=报名获得，关联收费编号）
   → 如无课程单价（纯报名费等）：
      不触发课时入账

3. 后续可继续对同一报名记录追加收费（分期场景）
   → 每次收费独立生成收费编号
   → 每次独立计算课时入账
   → 当累计实缴金额 = 应缴金额时，报名记录状态变更为「已收费」
```

### 8.2 部分收费规则

| 规则 | 说明 |
|------|------|
| 分期限额 | 单次最低实缴金额 1 元 |
| 次数不限制 | 同一报名记录可多次收费，直到缴清 |
| 课时入账 | 每次收费独立计算课时入账，按每次实缴金额除以课程单价 |
| 课时不足 1 时 | 单次实缴金额 < 课程单价时，不触发课时入账（费用照收，但课时不计） |
| 状态流转 | 累计已缴 < 应缴 → 部分收费；累计已缴 = 应缴 → 已收费 |

### 8.3 退费课时扣回计算

| 规则 | 公式 / 说明 |
|------|------|
| 扣回课时数 | `ceil(退费金额 / 课程单价)`，向上取整 |
| 扣回上限 | 不能超过该学生在对应收费记录下已获得的课时数 |
| 剩余不足处理 | 扣回后剩余课时 < 0 → 前端警告提示，人工确认后仍可执行 |
| 无课程单价 | 退费不涉及课时扣回，仅处理金额退还 |
| 多次退费 | 每次退费独立扣回课时，累计扣回 ≤ 该收费记录下累计获得课时数 |

**示例：**
- 学生张三报名数学提升班，课程单价 ¥200/课时，缴费 ¥2,000，获得 10 课时
- 退费 ¥900：扣回 `ceil(900/200) = ceil(4.5) = 5 课时`，剩余 5 课时
- 再次退费 ¥500：扣回 `ceil(500/200) = ceil(2.5) = 3 课时`，剩余 2 课时

### 8.4 审批阈值规则

| 配置项 | 默认值 | 说明 |
|------|------|------|
| `tuition.refund.approval_threshold` | `500.00` | 退费金额 ≤ 此值 → 直退；> 此值 → 需校长审批 |

规则：
- 退费金额为本次申请退费金额，非原收费总额
- 同一收费记录多次退费，每次独立判断是否超阈值
- 审批阈值通过 M0 系统配置管理，运营主管可修改（需 `system:config:edit` 权限）

### 8.5 赠送课时规则

| 规则 | 说明 |
|------|------|
| 赠送范围 | 单次 1~200 课时 |
| 关联课程 | 必须关联学生已报课程，课时入账到该课程下 |
| 课时类型 | 写入 M3 课时明细，类型标记为「赠送获得」 |
| 经手人 | 自动记录当前登录用户，不可修改 |
| 删除保护 | 删除赠送记录前校验剩余课时 ≥ 赠送课时，不足时警告 |
| 赠送原因 | 预设选项：促销活动 / 补偿 / 其他（其他需填写具体原因） |

### 8.6 费用类型

| 费用类型 | 编码 | 说明 | 是否涉及时课入账 |
|------|------|------|:--:|
| 报名费 | `REGISTRATION` | 报名时一次性收取，不涉及时课 | ❌ |
| 课时费 | `TUITION` | 按课程单价计算课时入账 | ✅ |
| 教材费 | `MATERIAL` | 教材/资料费，不涉及时课 | ❌ |
| 其他费用 | `OTHER` | 杂费、活动费等，不涉及时课 | ❌ |

### 8.7 状态流转总览

#### 收费记录状态

```
待收费 ──确认收费──→ 已收费 ──部分退费──→ 部分退费
  │                    │                    │
  │                    │  全部退费          │  全部退费
  │                    ↓                    ↓
  │                 已退费              已退费
  │
  └── 部分收费 ──继续收费──→ 已收费
```

#### 退费记录状态

```
待审批 ──审批通过──→ 已通过 ──系统执行──→ 已完成
   │                    （课时扣回+退款记录生成）
   │
   └── 驳回 ──→ 已驳回（终态，不可恢复）
   
（小额直退）──────→ 已完成（跳过审批）
```

#### 报名记录收费状态（M6 视角）

```
待收费 ──首次收费──→ 部分收费 ──缴清──→ 已收费
                         │
                         └── 全部退费 ──→ 已退费
```

## 11. 异常边界

### 11.1 课时计算异常

| 场景 | 处理方式 |
|------|------|
| 课程未设置单价 | 收费时不触发课时入账；退费时不触发课时扣回；前端显示提示信息 |
| 课程单价为 0 | 同"课程未设置单价"处理 |
| 实缴金额 < 课程单价 | 收费确认成功，但不触发课时入账（前端警告提示，人工确认） |
| 退费后课时余额为负 | 前端橙色警告提示，人工确认后仍可执行退费 |
| 赠送课时删除时余额不足 | 前端警告提示「该学生剩余课时（N）不足以扣回赠送课时（M）」，人工确认后仍可执行 |

### 11.2 数据一致性异常

| 场景 | 处理方式 |
|------|------|
| 报名记录已被删除 | 待收费列表不展示；如收费记录已关联，仍可查看但标注「原报名记录已删除」 |
| 原收费记录已被删除 | 退费记录不可创建；已有退费记录进入只读状态，标注「原收费记录已删除」 |
| 学生已停课/流失 | 仍可收费（历史缴费）；仍可退费（余额退还）；退费时课时扣回如不足需人工确认 |
| 并发收费（两人同时确认同一报名记录的收费） | 后端乐观锁或数据库行锁，后提交者提示「该报名记录已被他人修改，请刷新后重试」 |

### 11.3 审批异常

| 场景 | 处理方式 |
|------|------|
| 退费申请提交后审批人已离职/停用 | 审批列表仍显示待审批记录，其他有审批权限的用户可审批 |
| 审批阈值配置被设为负数 | 后端校验，阈值最小为 0（表示所有退费均需审批），拒绝负值 |
| 退费金额超过原收费总额 | 前端「可退上限」控制，后端二次校验，拒绝超过可退上限的请求 |
| 同一退费申请被多人同时审批 | 后端乐观锁，先成功者胜出，后提交者提示「该退费申请已被处理」 |

### 11.4 金额异常

| 场景 | 处理方式 |
|------|------|
| 实缴金额 ≤ 0 | 前端校验拦截，后端二次校验 |
| 退费金额 ≤ 0 | 前端校验拦截，后端二次校验 |
| 退费金额 > 可退上限 | 前端校验拦截，后端二次校验 |
| 赠送课时数 ≤ 0 或 > 200 | 前端校验拦截，后端二次校验 |
| 实缴金额超过 $999,999.99 | 后端校验拦截，提示「金额超出允许范围」 |

### 11.5 空状态与加载异常

| 状态 | 表现 |
|------|------|
| 待收费列表为空 | 空状态插图："暂无待收费记录"+ 提示"请先在报名管理中录入报名信息" |
| 已收费列表为空 | 空状态插图："暂无收费记录" |
| 退费列表为空 | 空状态插图："暂无退费记录" |
| 赠送记录列表为空 | 空状态插图："暂无赠送课时记录" |
| 搜索无结果 | "未找到匹配的记录"+「清空筛选」按钮 |
| 列表加载中 | 表格骨架屏（灰色条块） |
| 列表加载失败 | "数据加载失败"+「重试」按钮 |
| 表单提交失败（网络异常） | toast "网络异常，请重试" |
| 表单提交失败（业务异常） | toast 后端返回的具体错误信息 |
| 课程信息加载失败（收费确认弹窗） | 课时入账预览区显示「课程信息加载失败，请重试」+ 仍可提交（不阻止收费，仅不触发课时入账） |

## 13. 编号规则汇总

|------|------|------|------|
