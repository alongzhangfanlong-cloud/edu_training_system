# M5 排课管理

> **模块定位**：核心教务层（P0），左侧菜单高频独立顶层。运营主管每天高频使用的排课与课表管理工具。
> **路由**：`/schedule`
> **权限码**：`schedule:list`
> **后端模块**：`edu-module-schedule`
> **优先级**：P0，Phase 2（M4 班级管理完成后）

---

## 1. 模块概述

### 1.1 解决的问题

教育机构排课场景中，运营主管面临以下痛点：
- 手工在 Excel 或日历中排课，无法自动检测教师/教室/班级的时间冲突
- 批量排课（一学期）需逐条手动创建，耗时长且易出错
- 调课、取消排课时信息同步滞后，教师和家长无法及时获知变动
- 无法快速按教师/教室/班级维度查看课表，运营决策缺乏全局视角

### 1.2 模块目标

提供一套**可视化排课 + 三维冲突检测 + 课表管理**工具，实现：
- 单次排课和批量排课两种模式，覆盖日常和学期初两类场景
- 教师-教室-班级三维自动冲突检测，排课前即发现问题
- 周视图/月视图课表，支持按教师/教室/班级/科目多维度筛选
- 调课/取消操作带冲突重检和微信通知，保证信息实时同步

### 1.3 与其他模块的关系

```
M1 课程管理 ──→ 课程/科目/教室基础数据
M2 教师管理 ──→ 教师身份 + 可授科目，冲突检测依据
M4 班级管理 ──→ 班级上课规则（默认星期、时间段、教师、教室）← 排课的默认值来源
M5 排课管理 ──→ 生成排课记录 ──→ M8 考勤管理（签到依据）
                               ──→ M9 教学管理（课堂评价/成绩/作业的关联锚点）
                               ──→ M10 工作台（今日课表数据源）
```

- **排课基于班级**：选择班级后自动带出其上课规则（默认星期、时间段、教师、教室），允许覆盖
- **占用教室资源**：同一教室同一时段不可重复排课（硬约束，允许强制突破）
- **占用教师时间**：同一教师同一时段不可重复排课（硬约束，允许强制突破）
- **排课记录是签到的依据**：M8 考勤管理中的签到操作以排课记录为锚点

### 3.2 单次排课

#### 3.2.1 表单字段

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|------|------|
| 班级 | 远程搜索下拉 | ✅ | — | 选择后自动填充下方默认值（上课规则中的教师、教室、时间段），允许手动覆盖 |

| 结束时间 | 时间选择器 | ✅ | 班级规则的默认结束时间 | 必须晚于开始时间 |
| 教师 | 下拉选择 | ✅ | 班级规则的默认教师 | 仅列出该班级关联课程的「可授科目」匹配的教师；可手动切换 |

| 备注 | 文本域 | ❌ | — | 最多 200 字符 |

#### 3.2.2 交互流程

```
1. 运营主管选择班级
   ↓
2. 系统自动带出班级上课规则中的默认值：
   - 默认教师 → 教师下拉框
   - 默认教室 → 教室下拉框
   - 默认开始时间 / 结束时间 → 时间选择器
   - 课程名称 → 灰色只读展示
   ↓
3. 运营主管选择上课日期（默认当天），可手动调整教师/教室/时间
   ↓
4. 点击「提交排课」
   ↓
5. 系统执行三维冲突检测（§4）
   ├── 无冲突 → 排课成功 → toast "排课成功" → 清空表单 → 刷新下方列表
   └── 有冲突 → 弹出冲突详情弹窗（§4.4）
         ├── 用户选择「强制排课」→ 忽略冲突写入 → toast "已强制排课" → 刷新列表
         └── 用户选择「取消」→ 关闭弹窗，表单保留
```

|------|------|

### 3.3 批量排课

#### 3.3.1 表单字段

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:--:|------|------|
| 班级 | 远程搜索下拉（多选） | ✅ | — | 支持多选，最多同时选 10 个班级 |
| 起始日期 | 日期选择器 | ✅ | 当天 | 不可选择已过日期 |
| 结束日期 | 日期选择器 | ✅ | 30 天后 | 不可早于起始日期，最大跨度 180 天 |
| 排课状态 | 下拉单选 | ✅ | 正常 | 正常 / 补课 |
| 备注 | 文本域 | ❌ | — | 对整批排课生效，最多 200 字符 |

> 批量排课不提供教师/教室/时间的手动选择。每个班级的排课依据其**上课规则中的「每周几」和「时间段」**自动计算生成。如需单独调整某一天的排课，在生成后在课表视图页操作。

#### 3.3.2 交互流程

```
1. 运营主管选择多个班级（最多 10 个）
   ↓
2. 选择起始日期 + 结束日期
   ↓
3. 点击「预览排课计划」
   ↓
4. 系统根据每个班级的上课规则自动计算排课计划：
   - 班级 A：每周一、三 08:30-10:00，教师=李老师，教室=201
     → 在日期范围内生成所有周一、周三的排课
   - 班级 B：每周六 14:00-16:00，教师=王老师，教室=302
     → 生成所有周六的排课
   ↓
5. 展示预览表格（§3.3.3），高亮标注冲突项
   ↓
6. 运营主管可逐条勾选/取消勾选，剔除不想生成的排课
   ↓
7. 点击「确认排课」
   ↓
8. 系统对勾选的排课执行三维冲突检测（§4）
   ├── 全部无冲突 → 批量写入 → toast "成功生成 N 条排课" → 清空表单 → 刷新列表
   └── 存在冲突 → 弹出冲突汇总弹窗：
         展示冲突条目 + 冲突详情
         ├── 「跳过冲突项，生成其余排课」→ 无冲突的全部生成，冲突项跳过 → toast "成功生成 M 条排课，N 条因冲突跳过"
         ├── 「强制全部排课」→ 全部写入（冲突项标记「强制排课」）→ toast "已强制排课 N 条"
         └── 「取消」→ 返回预览页，保留表单和勾选状态
```

## 4. 三维冲突检测

### 4.1 检测维度

| 维度 | 检测逻辑 | 严重程度 |
|------|------|:--:|
| **教师冲突** | 同一教师，同一日期及时段（时间有交集），已有其他「正常/补课」状态的排课 | 高 |
| **教室冲突** | 同一教室，同一日期及时段（时间有交集），已有其他「正常/补课」状态的排课 | 高 |
| **班级冲突** | 同一班级，同一日期及时段（时间有交集），已有其他「正常/补课」状态的排课 | 高 |

**时间交集判定规则**：两个排课的时间段 `[A_start, A_end)` 与 `[B_start, B_end)` 满足 `A_start < B_end AND A_end > B_start` 即为冲突。精确相等（完全重叠）是最常见的冲突形态，但部分重叠也必须检出。

**排除项**：
- 已取消（`status = CANCELLED`）的排课不参与冲突检测
- 已调课（`status = RESCHEDULED`）的排课不参与冲突检测（原时段已释放）
- 停课（`status = SUSPENDED`）的排课不参与冲突检测（当次已停）
- 单个排课正在自我编辑/调课时，需排除自身（`scheduleId != currentId`）

### 4.2 检测时机

| 时机 | 场景 | 说明 |
|------|------|------|
| 提交前 | 单次排课提交、批量排课确认提交、调课提交 | 提交即触发，有冲突先弹窗不落库 |
| 预览时 | 批量排课预览 | 轻量检测，仅标注不阻止 |

### 4.3 后端冲突检测 SQL 模式

```sql
-- 教师冲突检测
SELECT * FROM edu_schedule
WHERE teacher_id = #{teacherId}
  AND schedule_date = #{scheduleDate}
  AND start_time < #{endTime}
  AND end_time > #{startTime}
  AND status IN ('NORMAL', 'MAKEUP')
  AND id != #{excludeScheduleId}
  AND is_deleted = 0;

-- 教室冲突检测（同理，替换为 room_id）
-- 班级冲突检测（同理，替换为 class_id）
```

### 4.5 强制排课

| 场景 | 行为 |
|------|------|

```
1. 点击「调课」→ 弹出调课弹窗（原信息展示 + 新信息编辑）
   ↓
2. 修改需要调整的字段 + 填写调课原因（必填）
   ↓
3. 点击「确认调课」
   ↓
4. 系统执行三维冲突检测（§4）：
   ├── 无冲突 → 继续
   └── 有冲突 → 弹出冲突详情弹窗（同 §4.4）
         ├── 「强制调课」→ 继续
         └── 「取消」→ 返回弹窗修改
   ↓
5. 后端：
   - 原排课记录状态更新为「已调课」，记录新排课 ID（`rescheduled_to_id`）
   - 创建新排课记录（状态为「正常」，`rescheduled_from_id` 指向原记录）
   - 新排课继承原排课的班级、课程（不可改），使用新日期/时间/教师/教室
   - 异步触发微信通知：
     ├── 通知教师："您在 07-16 08:30 的三1班数学课已调至 07-18 14:00，教师/教室不变"
     └── 通知家长："07-16 08:30 的数学课已调至 07-18 14:00，教师/教室不变"
   ↓
6. 前端：
   - toast "调课成功，已通知教师和家长"
   - 关闭弹窗
   - 刷新课表/列表（原排课变灰 + 新排课出现）
```

#### 6.3.3 调课约束

| 约束 | 说明 |
|------|------|
| 不可改班级/课程 | 调课只调整时间/地点/教师，关联的班级和课程不可更改 |
| 新日期不可为已过日期 | 与排课操作相同，`disabledDate` 排除 `< today` 的日期 |
| 必须有变更 | 若新排课信息与原排课完全一致，提交时提示"未检测到任何变更" |

```
   正常 + 补课 + 强制排课 ──调课──→ 原记录已调课 + 新记录正常

   补课 ── 不可取消/调课? 不:
   补课 (MAKEUP) 与正常 (NORMAL) 同等对待，可取消/可调课

   停课 ── 由 M8 考勤管理的教师请假审批流程触发，不由 M5 直接操作
```

## 8. 业务规则

### 8.1 排课创建规则

| 规则编号 | 规则 | 说明 |
|:--:|------|------|
| R01 | 班级必选 | 排课必须关联一个班级，不可独立存在 |
| R02 | 时间合法性 | 结束时间必须严格晚于开始时间 |
| R03 | 日期不可逆 | 不可为已过日期（`schedule_date < today`）创建排课 |
| R04 | 批量日期范围 | 起始日期不可晚于结束日期，跨度最大 180 天 |
| R05 | 批量班级上限 | 一次性最多为 10 个班级批量排课 |
| R06 | 上课规则必填 | 用于批量排课的班级必须有完整的上课规则（每周几 + 时间段 + 教师 + 教室），否则跳过并提示 |
| R07 | 教师授课匹配 | 排课所选的教师须在「可授科目」中覆盖该班级关联课程的科目 |

### 8.2 冲突检测规则

| 规则编号 | 规则 | 说明 |
|:--:|------|------|
| R08 | 三维独立检测 | 教师、教室、班级三个维度独立检测，任一命中即为冲突 |
| R09 | 时间交集判定 | `start1 < end2 AND end1 > start2` 即冲突，不限完全重叠 |
| R10 | 排除已失效排课 | 已取消/已调课/停课状态的排课不参与冲突检测 |
| R11 | 排除自身 | 调课场景检测新时间时排除当前记录自身 |
| R12 | 强制排课允许 | 用户可选择忽略冲突强制排课，记录 `force_flag=1` |

### 8.3 调课/取消规则

| 规则编号 | 规则 | 说明 |
|:--:|------|------|
| R13 | 仅可操作未来排课 | 已过日期的排课不可取消/调课 |
| R14 | 取消必填原因 | 取消原因非空，最长 200 字符 |
| R15 | 调课必填原因 | 调课原因非空，最长 200 字符 |
| R16 | 调课不可改班级/课程 | 调课时仅可调整日期、时间、教师、教室 |
| R17 | 调课须有变更 | 新排课信息必须与原排课至少有一项不同 |
| R18 | 调课触发冲突重检 | 调课的新时段执行完整三维冲突检测 |

### 8.4 通知规则

| 规则编号 | 规则 | 说明 |
|:--:|------|------|
| R19 | 取消通知范围 | 取消排课时通知任课教师 + 班级所有学生家长 |
| R20 | 调课通知范围 | 调课时通知任课教师 + 班级所有学生家长 |
| R21 | 通知内容 | 包含课程、班级、原时段、新时段（调课）、原因 |
| R22 | 通知异步 | 通知为异步操作，不阻塞排课/调课/取消的主流程 |

### 9.3 冲突检测伪代码

```java
// 单条排课冲突检测
public List<ConflictDetail> detectConflicts(ScheduleDTO dto, Long excludeScheduleId) {
    List<ConflictDetail> conflicts = new ArrayList<>();

    // 1. 教师冲突
    List<Schedule> teacherConflicts = scheduleMapper.selectByTeacherConflict(
        dto.getTeacherId(), dto.getScheduleDate(),
        dto.getStartTime(), dto.getEndTime(), excludeScheduleId);
    if (!teacherConflicts.isEmpty()) {
        conflicts.add(ConflictDetail.of(ConflictType.TEACHER, teacherConflicts));
    }

    // 2. 教室冲突
    List<Schedule> roomConflicts = scheduleMapper.selectByRoomConflict(
        dto.getRoomId(), dto.getScheduleDate(),
        dto.getStartTime(), dto.getEndTime(), excludeScheduleId);
    if (!roomConflicts.isEmpty()) {
        conflicts.add(ConflictDetail.of(ConflictType.ROOM, roomConflicts));
    }

    // 3. 班级冲突
    List<Schedule> classConflicts = scheduleMapper.selectByClassConflict(
        dto.getClassId(), dto.getScheduleDate(),
        dto.getStartTime(), dto.getEndTime(), excludeScheduleId);
    if (!classConflicts.isEmpty()) {
        conflicts.add(ConflictDetail.of(ConflictType.CLASS, classConflicts));
    }

    return conflicts;
}
```

## 11. 异常边界

### 11.1 冲突处理

| 场景 | 处理方式 |
|------|------|
| 提交前冲突检测 | 弹窗展示冲突详情（§4.4），用户选择强制排课或返回修改 |
| 预览阶段冲突标注 | 预览表格红底高亮 + tooltip 详情，不阻止继续操作 |
| 批量提交部分冲突 | 弹窗展示冲突汇总，用户选择跳过/强制/取消（§4.4.2） |
| 调课新时段冲突 | 同提交前冲突检测流程 |
| 强制排课标记 | `force_flag=1`，工作台预警列表持续可见 |

### 11.2 日期边界

| 场景 | 处理方式 |
|------|------|
| 选择已过日期排课 | 日期选择器 `disabledDate` 禁止选择，提交时二次校验 |
| 取消/调课已过日期的排课 | 操作按钮灰显 + tooltip "已过上课日期，不可操作" |
| 批量排课起止日期倒挂 | 表单校验失败，提示"结束日期不可早于起始日期" |
| 批量排课跨度超过 180 天 | 表单校验失败，提示"日期跨度不可超过 180 天" |

### 11.3 数据异常

| 场景 | 处理方式 |
|------|------|
| 班级无上课规则 | 选择该班级时提示"该班级未配置上课规则，请在班级管理中完善"，不可提交 |
| 班级上课规则无教师 | 自动填充时教师为空，标记为必填 |
| 班级上课规则无教室 | 自动填充时教室为空，标记为必填 |
| 班级上课规则时间段非法 | 自动填充时校验不过，阻断提交 |
| 排课记录被他人同时操作 | 后端使用乐观锁（`update_time` 版本号），冲突时提示"该排课已被他人修改，请刷新后重试" |
| 取消时已有签到记录 | toast 警告提示，签到记录标记为失效 |

### 11.4 依赖数据不可用

| 场景 | 处理方式 |
|------|------|
| 班级列表接口失败 | 下拉框显示"加载失败"+「重试」，排课表单禁用提交 |
| 教师列表接口失败 | 下拉框显示"加载失败"+「重试」 |
| 教室列表接口失败 | 下拉框显示"加载失败"+「重试」 |
| 课表数据加载失败 | 整体显示"加载失败"+「重试」 |

### 11.5 并发操作

| 场景 | 处理方式 |
|------|------|
| 同一排课被两个运营主管同时取消 | 先成功的正常处理，后到的返回"该排课已被取消" |
| 同一排课被同时取消和调课 | 先到达的请求正常处理，后到的返回"排课状态已变更，请刷新" |
| 批量排课提交时部分班级规则已变更 | 以提交时实时读取的班级规则为准（非预览时缓存的规则） |

### 11.6 微信通知异常

| 场景 | 处理方式 |
|------|------|
| 微信订阅消息发送失败 | 不阻塞主流程，记录失败日志，工作台待办中展示"通知发送失败" |
| 家长未订阅消息 | 跳过，不报错 |
| 教师未绑定小程序 | 跳过该教师的通知，不报错 |
