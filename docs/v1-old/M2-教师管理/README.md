# M2 教师管理

> **模块定位**：基础资源层（P0），管理教师档案、可授科目关联、资质信息。
> **后端包**：`edu-module-teacher`
> **菜单路径**：基础管理 > 教师管理
> **适用角色**：校长、运营主管（教师不可访问此模块）

---

## 1. 模块概述与定位

### 1.1 模块职责

教师管理作为「基础资源层」核心模块，负责维护机构全体教师的基础档案。教师是后续**班级管理（M4）**、**排课管理（M5）**、**考勤管理（M8）**、**教学管理（M9）**等模块的关键依赖资源，必须最先完成基础数据沉淀。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| 教师档案 CRUD | 姓名、手机号、入职日期、在职/离职状态 |
| 可授科目关联 | 多对多关联，以标签形式编辑和展示 |
| 教师资质信息 | 教师资格证、学历、教龄等附加信息（非必填） |
| 离职前置检查 | 离职时检查是否有未结课班级，有则阻止并提示 |
| 在教班级展示 | 只读展示该教师当前关联的班级列表 |

### 1.3 依赖关系

```
M0 系统管理（sys_user 关联）
  │
  └── M1 课程管理（科目数据）
        │
        └── M2 教师管理 ← 本模块
              │
              ├── M4 班级管理（引用教师）
              │     └── M5 排课管理（引用教师+班级）
              │           └── M8 考勤管理（引用教师+排课）
              │                 └── M9 教学管理（引用教师）
```

- **上游依赖**：M0 系统管理（`sys_user` 关联）、M1 课程管理（科目数据用于可授科目选择）
- **下游被依赖**：M4 班级管理、M5 排课管理、M8 考勤管理、M9 教学管理

### 1.4 与 sys_user 的关系

教师档案表与 `sys_user` 通过 **手机号（mobile）** 关联：

```
sys_user                        教师档案表
┌──────────────────┐           ┌──────────────────────┐
│ id               │           │ id                   │
│ user_name        │           │ name (姓名)           │
│ password         │           │ mobile (手机号) ──────┼──→ sys_user.mobile
│ real_name        │           │ entry_date (入职日期)  │
│ mobile ──────────┼──→ 关联   │ status (在职/离职)     │
│ status (启用/停用) │          │ education (学历)      │
│ ...              │           │ teaching_years (教龄) │
│ wx_openid        │           │ cert_no (资格证号)    │
└──────────────────┘           │ user_id → sys_user.id │
                               └──────────────────────┘
```

**关联规则**：
1. 新增教师时，系统根据手机号查找 `sys_user`：存在且角色含"教师"则直接关联；存在但角色不含教师则提示"该手机号已注册为非教师用户"；不存在则自动创建 `sys_user` 并分配教师角色
2. 教师离职时，对应的 `sys_user` 状态同步变更为停用
3. 删除教师时，关联的 `sys_user` 同步删除（逻辑删除）
4. 教师档案表存 `user_id` 字段指向 `sys_user.id`，作为外键关联

### 4.5 手机号唯一性校验

| 项目 | 说明 |
|------|------|
| 校验时机 | 手机号输入框失焦时触发 |
| 校验方式 | 调用 `GET /api/v1/teacher/check-mobile?mobile=xxx&excludeId=xxx`（编辑时传 `excludeId` 排除自身） |
| 校验中 | 输入框右侧 loading 旋转图标 |
| 校验通过 | 绿色勾 ✓ |
| 校验失败 | 红色叉 ✗ + 下方红色提示"该手机号已被其他教师使用" |
| 硬阻断 | 校验失败时「确定」按钮仍可点击，但提交时再次校验并阻止 |

**竞态保护**：使用远程下拉搜索模式一的防抖 + 竞态模式（300ms 防抖 + `searchSeq` 序号）。

### 4.6 新增时自动创建 sys_user

新增教师提交时，后端逻辑：

```
1. 校验手机号唯一性（教师档案表中无重复）
2. 查找 sys_user WHERE mobile = 提交的手机号
   ├── 存在且角色含"教师" → 直接关联 user_id，不再创建
   ├── 存在但角色不含"教师" → 返回错误 "该手机号已注册为非教师用户，请更换手机号"
   └── 不存在 → 自动创建 sys_user：
        ├── user_name = 手机号
        ├── password = BCrypt(手机号后6位)
        ├── real_name = 教师姓名
        ├── mobile = 手机号
        ├── status = 0 (正常)
        └── 分配"教师"角色
3. 创建教师档案记录，设置 user_id
4. 保存教师-科目关联关系
```

### 4.7 交互流程

| 操作 | 行为 |
|------|------|
| 打开（新增） | 空表单，状态默认"在职"，入职日期默认当天 |
| 打开（编辑） | 调用 `GET /api/v1/teacher/{id}` → 填充表单（含科目回填，已选科目在下拉框中默认勾选） |

| 取消 | 有修改 → 确认弹窗"放弃修改？"；无修改 → 直接关闭 |

## 5. 离职/复职操作

### 5.1 流程

在职教师 → 点击操作列「离职」→ 触发离职前置检查 → 通过则二次确认 → 调用 `PUT /api/v1/teacher/{id}/status` → 同步停用 sys_user → 刷新列表

### 5.2 离职前置检查

**触发时机**：操作列点击「离职」按钮后，先调用检查接口，再决定是否弹出确认框。

**检查接口**：`GET /api/v1/teacher/{id}/check-before-leave`

**检查逻辑**：查询该教师当前关联的**未结课班级**（班级状态为「进行中」）。

**返回数据**：
```json
{
  "canLeave": false,
  "activeClasses": [
    { "id": 1, "name": "初三数学冲刺班", "studentCount": 12 },
    { "id": 2, "name": "高二物理提高班", "studentCount": 8 }
  ],
```

## 7. 业务规则

### 7.1 手机号唯一性

- 教师档案表中 `mobile` 字段全局唯一
- 新增时校验：`mobile` 不可与已有教师（含已离职）重复
- 编辑时校验：`mobile` 不可与其他教师重复（排除自身）
- 提示文案："该手机号已被其他教师使用"

### 7.2 离职前置检查

- 教师离职前必须通过「未结课班级检查」
- 存在未结课班级（班级状态为"进行中"）时，**禁止离职**
- 前端先调检查接口获取班级列表，有未结课班级则弹出警告弹窗，**不可绕过**
- 后端同样做校验：`PUT /api/v1/teacher/{id}/status` 接口内检查，有未结课班级返回 `400` + 班级列表

### 7.3 删除限制

- 仅允许删除**离职状态**的教师
- 在职教师：操作列不显示「删除」按钮
- 后端做双重校验：删除接口检查教师状态，在职教师返回 `400 "在职教师不可删除，请先办理离职"`
- 已关联班级的教师（即使班级已结课）仍可删除（历史数据保留在班级记录中）
- 删除教师时，关联的 `sys_user` 同步逻辑删除

### 7.4 与 sys_user 同步规则

| 教师操作 | sys_user 联动 |
|------|------|
| 新增教师 | 自动创建 sys_user（如手机号无冲突）+ 分配教师角色 |
| 编辑手机号 | 同步更新 sys_user.mobile 和 sys_user.user_name |
| 编辑姓名 | 同步更新 sys_user.real_name |
| 离职 | sys_user.status = 停用(1) |
| 复职 | sys_user.status = 正常(0) |
| 删除教师 | sys_user.is_deleted = 1（逻辑删除） |

### 7.5 可授科目引用一致性

- 当 M1 课程管理中某科目被删除或停用时，需要检查是否有教师关联了该科目
- 如有教师关联，提示"该科目下有 {N} 位教师关联，请先移除关联"
- 科目编辑时的引用保护在 M1 模块处理，M2 模块只需确保：
  - 列表页展示科目名称时，即使科目已被删除也显示（显示为灰色 + 划线）
  - 编辑弹窗加载科目列表时仅显示生效中的科目

## 8. 数据模型要点

### 8.1 核心表结构

#### 教师档案表 `edu_teacher`

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| id | BIGINT PK | ✅ | 主键，自增 |
| user_id | BIGINT | ✅ | 关联 sys_user.id |
| name | VARCHAR(20) | ✅ | 教师姓名 |
| mobile | VARCHAR(11) | ✅ | 手机号，唯一索引 `uk_mobile` |
| entry_date | DATE | ✅ | 入职日期 |
| status | TINYINT | ✅ | 0-在职，1-离职，默认 0 |
| education | VARCHAR(20) | | 学历 |
| teaching_years | INT | | 教龄（年） |
| cert_no | VARCHAR(32) | | 教师资格证编号 |
| graduate_school | VARCHAR(100) | | 毕业院校 |
| major | VARCHAR(50) | | 专业 |
| remark | VARCHAR(500) | | 备注 |
| create_time | DATETIME | ✅ | 创建时间 |
| update_time | DATETIME | ✅ | 更新时间 |
| is_deleted | TINYINT | ✅ | 逻辑删除，默认 0 |

**索引**：
- `uk_mobile` UNIQUE (`mobile`)
- `uk_user_id` UNIQUE (`user_id`)
- `idx_status` (`status`)
- `idx_entry_date` (`entry_date`)

#### 教师-科目关联表 `edu_teacher_subject`

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| id | BIGINT PK | ✅ | 主键，自增 |
| teacher_id | BIGINT | ✅ | 教师 ID |
| subject_id | BIGINT | ✅ | 科目 ID（来自 edu_subject） |
| create_time | DATETIME | ✅ | 创建时间 |

**索引**：
- `uk_teacher_subject` UNIQUE (`teacher_id`, `subject_id`)
- `idx_subject_id` (`subject_id`)

### 8.2 与 sys_user 的关联

教师档案表通过 `user_id` 外键关联 `sys_user.id`，同时通过 `mobile` 字段与 `sys_user.mobile` 保持数据一致性。

**数据同步时机**：
- 新增教师：自动创建或关联 sys_user
- 编辑教师手机号：同步更新 sys_user.mobile 和 user_name
- 离职/复职：同步切换 sys_user.status
- 删除教师：同步逻辑删除 sys_user

### 8.3 与班级的关联

教师与班级的关系由 M4 班级管理维护（`edu_class` 表中有 `teacher_id` 字段），M2 教师管理只做只读查询。

查询逻辑：`SELECT * FROM edu_class WHERE teacher_id = ? AND status = '进行中' AND is_deleted = 0`

## 10. 异常边界

### 10.1 业务异常

| 场景 | 错误码 | 提示信息 | 处理方式 |
|------|:--:|------|------|
| 手机号已被使用（新增） | 400 | "该手机号已被其他教师使用" | 前端校验 + 后端校验，红色 toast |
| 手机号已被使用（编辑） | 400 | "该手机号已被其他教师使用" | 同上 |
| 手机号已注册为非教师用户 | 400 | "该手机号已注册为非教师用户，请更换手机号" | 后端返回，前端 toast |
| 在职教师不可删除 | 400 | "在职教师不可删除，请先办理离职" | 前端隐藏删除按钮 + 后端校验 |
| 离职前有未结课班级 | 400 | "该教师还有 {N} 个未结课的班级，请先更换班级教师后再办理离职" | 前端弹窗列出班级详情 + 后端校验 |
| 可授科目至少选 1 个 | 校验 | "请至少选择一个可授科目" | 前端表单校验，提交前阻止 |
| 入职日期晚于今天 | 校验 | "入职日期不可晚于今天" | 前端日期选择器限制 + 后端校验 |
| 教师不存在 | 404 | "教师信息不存在" | 后端返回 404 |
| 数据已被他人修改 | 409 | "数据已被他人修改，请刷新后重试" | 后端乐观锁检查（可选） |

### 10.2 系统异常

| 场景 | 处理 |
|------|------|
| 网络超时（> 10s） | toast "网络超时，请检查网络后重试" |
| 服务器 500 错误 | toast "服务器异常，请稍后重试" |
| sys_user 创建失败 | 后端事务回滚（教师记录 + 科目关联全部回滚），toast "创建教师失败，请重试" |
| 科目列表加载失败 | 科目选择器显示"加载失败" + 重试链接 |
| 离职检查接口超时 | toast "检查失败，请重试"，不弹出确认框 |

### 10.3 并发场景

| 场景 | 处理 |
|------|------|
| 两人同时编辑同一教师 | 后提交者覆盖先提交者（最后写入胜出）；可选乐观锁版本号 |
| 教师离职时班级被他人修改 | 离职检查接口实时查询，确保数据时效性 |
| 手机号校验与提交之间被人抢占 | 提交时后端再次校验唯一性，如已被占用则返回错误 |

### 10.4 数据一致性

| 场景 | 处理 |
|------|------|
| 编辑教师手机号 → sys_user.mobile 更新失败 | 事务回滚，整体失败 |
| 删除教师 → sys_user 删除失败 | 事务回滚，整体失败 |
| M1 科目被删除 → 教师仍关联 | 教师列表/详情中该科目显示为灰色 + 删除线；编辑教师时该科目不出现在可选项但保留已选（不可新增） |
| sys_user 被手动删除 → 教师记录还在 | 教师详情中「关联账号」显示"未关联"，姓名旁显示 ⚠ 警告图标 |

### 10.5 边界值

| 字段 | 边界值 | 处理 |
|------|------|------|
| 姓名 | 1 字符 / 20 字符 / 含特殊字符 | 1-20 字符合格；`<script>` 等 XSS 字符后端转义 |
| 手机号 | 非 1 开头 / 10 位 / 12 位 / 含字母 | 前端正则 `^1\d{10}$` 过滤，后端再校验 |
| 教龄 | 0 / 99 / 100 / -1 | 0-99 范围内合格，超出范围提示"教龄应在 0-99 之间" |
| 入职日期 | 1900-01-01 / 今天 / 明天 | 不早于 1900-01-01，不晚于今天 |
| 备注 | 500 字 / 501 字 | 500 字合格，超出则截断或前端限制输入 |
| 可授科目数 | 0 / 1 / 100 | 至少 1 个，无上限（按机构实际科目数量） |
