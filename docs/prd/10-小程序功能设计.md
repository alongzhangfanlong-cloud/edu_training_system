## 2. 登录认证

**适用**：家长端和教师端小程序

### 2.1 设计方案：微信静默登录

核心原则：用户只在首次点击一次「手机号授权」按钮，后续打开小程序完全无感。

### 2.2 首次登录流程

```
用户打开小程序
  │
  ├─1─ wx.login()                      静默，无弹窗，获取 code
  │
  ├─2─ 显示「微信手机号一键登录」按钮      用户点一次授权
  │     button open-type="getPhoneNumber"
  │
  ├─3─ 拿到 code + 加密手机号
  │     POST /api/v1/auth/wechat-bind
  │     → 后端解密手机号 → 按 mobile 匹配 sys_user
  │       → 匹配成功：绑定 wx_openid → 签发 JWT → 登录成功
  │       → 匹配失败：返回「未关联账户，请联系机构」
  │
  └─4─ 存 token → 按角色进入对应首页
```

### 2.3 静默登录流程（第二次及以后）

```
用户打开小程序
  │
  ├─1─ wx.login()                      静默，获取 code
  │
  ├─2─ POST /api/v1/auth/wechat-login
  │     → 后端 code 换 openid → 查 sys_user.wx_openid
  │       → 找到：签发新 JWT → 登录成功
  │       → 未找到：回退到首次登录流程（显示授权按钮）
  │
  └─3─ 用户完全无感，直接进入首页
```

### 2.4 Token 刷新

- accessToken 2 小时过期，refreshToken 7 天
- 小程序每次启动时检查 token 有效性
- 过期 → 自动调 `POST /api/v1/auth/refresh` → 无感续期
- refreshToken 也过期 → 重新走静默登录

### 2.5 小程序页面状态

**登录中**（静默登录执行中）：
- 全屏 loading："正在登录…" + 品牌 logo
- 最长等待 5 秒，超时显示错误页 +「重试」按钮

**首次使用**（未绑定 openid）：
- 显示品牌页
- 「微信手机号一键登录」按钮（`open-type="getPhoneNumber"`）
- 下方小字："登录即表示同意《用户协议》"

**登录失败**（手机号未关联）：
- 空状态插图："未找到您的账户信息"
- 提示文字："请联系机构将您的手机号录入系统"
- 「联系机构」按钮（拨打机构电话）

### 2.6 新增 API

| 接口 | 入参 | 返回 | 说明 |
|------|------|------|------|
| `POST /api/v1/auth/wechat-login` | `{ code }` wx.login 返回 | `{ accessToken, refreshToken, userInfo }` 或 401 | code → openid → 查 wx_openid → 签发 JWT |
| `POST /api/v1/auth/wechat-bind` | `{ code, encryptedPhone, iv }` getPhoneNumber 返回 | `{ accessToken, refreshToken, userInfo }` 或 401 | 解密手机号 → 匹配 mobile → 绑定 openid → 签发 JWT |

### 2.7 数据变更

- `sys_user` 表新增 `wx_openid` 字段（VARCHAR 64，唯一索引，可空）
- 家长角色用户：`password` 字段存随机值（不使用），`username` 默认取手机号

### 2.8 家长账号自动注册

**触发时机**：PC 端录入学生信息，填写家长手机号

**后端逻辑**：
1. 按手机号查 `sys_user WHERE mobile = ?`
2. 不存在 → 自动插入：`username=手机号, password=随机UUID(不使用), role=家长, status=正常`
3. 存在 → 跳过
4. 关联学生档案 ↔ 家长 user_id

**结果**：家长首次打开小程序 → 授权手机号 → wx_openid 绑定到已有的 sys_user → 直接看到关联的孩子信息

### 2.9 后端依赖

- 微信 `jscode2session` API：`GET https://api.weixin.qq.com/sns/jscode2session?appid=APPID&secret=SECRET&js_code=CODE&grant_type=authorization_code`
- 微信手机号解密：AES-128-CBC，使用 session_key 解密 `getPhoneNumber` 返回的 encryptedData
- `wechat.app-id` 和 `wechat.app-secret` 写在 `application.yml`

## 4. 家长端页面设计

### 4.1 首页（动态）Tab

**定位**：家长打开小程序的默认首页。以时间线展示所有孩子的动态更新，多孩家庭以折叠面板（手风琴）展示，每孩独立一条动态流。

#### 4.1.1 孩子动态时间线

**规则**：
- 多孩子按孩子分组，每个孩子一个折叠面板
- 面板标题：孩子姓名 + 年级 + 当日最新动态摘要（如「张三 · 三年级 · 今天已到校」）
- 默认展开第一个孩子面板，其余折叠
- 每个孩子面板内为按时间倒序的动态卡片流

**动态卡片类型**：

##### 签到通知卡片（N07 考勤管理）
- 预览：「已于 15:02 到校」
- 展开：签到时间、课程名称、考勤状态（到校/迟到/缺勤）
- 数据来源：教师在小程序签到 Tab 完成批量签到后，系统自动推送

##### 教评学通知卡片（N05 家校沟通 → 教评学）
- 预览：「今日课堂表现 ⭐⭐⭐⭐」+ 评语前 30 字
- 展开：完整评语 + 各维度星级详情（听讲专注度/课堂参与/作业完成/综合表现）
- 数据来源：教师在 PC 端或小程序完成课堂评价后推送

##### 作业通知卡片（N05 家校沟通 → 课后作业）
- 预览：「语文作业：」+ 内容前 30 字
- 展开：完整作业描述 + 附件图片列表（可点击放大查看）
- 数据来源：教师在 PC 端或小程序教学 Tab 发布作业后推送

##### 成绩发布通知卡片（N05 家校沟通）
- 预览：「数学月考：92 分」
- 展开：本次成绩详情（含分数、排名、班级均分对比）
- 数据来源：教师在 PC 端录入成绩后推送

#### 4.1.2 [P2] 积分余额展示 + 积分商城入口

**位置**：首页顶部固定区域（动态列表上方）

| 元素 | 说明 |
|------|------|
| 积分余额 | 展示当前家长所有孩子合计积分，如「全家积分：1,280」 |
| 积分商城入口 | 胶囊按钮「积分商城 →」，点击跳转至「我的」Tab 下积分兑换模块 |
| 积分获取提示 | 轻提示：「签到 +5 / 评价 +3」，无操作时 2 秒自动消失 |

**状态**：P2 迭代追加。P0 阶段积分模块仅在 PC 管理后台运营端实现，小程序端积分兑换推迟到后续版本。

### 4.2 消息 Tab

**定位**：以事件为维度的通知汇总，纯列表形式，不分孩子，用于回溯查看所有审批结果和系统通知。

**与首页动态 Tab 的分工**：
- **首页（动态）**：以孩子为维度的内容流，展示教学互动类动态（签到/评价/作业/成绩），分组折叠
- **消息 Tab**：以事件为维度的通知列表，聚焦审批结果和系统级通知，不区分孩子

#### 4.2.1 请假审批结果通知

- 列表项：孩子姓名 + 请假日期 + 审批结果（已通过/已驳回）
- 已驳回展示驳回原因
- 点击展开完整请假详情（日期范围/类型/原因/审批人/审批时间）
- 数据来源：教师或运营主管在 PC 端或小程序审批请假后推送

#### 4.2.2 代课/调课/停课通知

- 列表项：课程名称 + 变更类型 + 变更日期
- 点击展开：原排课信息 → 变更后信息（教师/时间/教室变更明细）
- 数据来源：运营主管在 PC 端排课管理中进行代课/调课/停课操作后推送

#### 4.2.3 系统通知

- 机构公告（如节假日放假通知、家长会通知）
- 系统维护通知
- 其他平台级推送

#### 4.2.4 消息列表通用规则

- 按时间倒序排列，所有类型混合展示
- 每条消息标注：类型图标 + 标题 + 时间 + 已读/未读状态
- 未读消息在 Tab 图标上显示角标数字
- 点击消息进入详情或跳转对应页面
- MVP 阶段混合列表即可，后续可加类型筛选

#### 4.3.2 个人头部

| 元素 | 说明 |
|------|------|
| 头像 | 微信头像（`wx.getUserProfile` 获取） |
| 昵称 | 微信昵称 |
| 绑定手机号 | 脱敏显示，如 `138****5678`；未绑定时显示「绑定手机号」引导按钮 |

**手机号绑定流程**：
- 点击手机号区域 → 调起微信手机号快速验证组件（`button open-type="getPhoneNumber"`）
- 获取加密手机号 → 后端解密 → 写入家长档案 → 同时触发孩子匹配
- 绑定后该入口变为仅查看（脱敏展示），长按或点击可解绑/换绑

**换绑处理**：
- 换绑手机号后，重新执行孩子匹配
- 旧手机号关联的孩子自动解除

#### 4.3.3 我的孩子

**卡片内容**（每个孩子一张）：

| 字段 | 说明 |
|------|------|
| 姓名 | 学生姓名 |
| 年级 | 当前年级（如「三年级」） |
| 在读班级数 | 如「2 个班」 |
| 剩余课时汇总 | 所有在读班级剩余课时之和，如「剩余 18 课时」 |

**交互**：
- 横向滑动浏览多个孩子
- 点击卡片 → 进入「孩子详情页」（见 4.3.7）
- 只有一个孩子时卡片居中展示，无需滑动
- 无孩子时展示空状态：「暂无关联孩子，请联系机构绑定」，下方提供机构电话快捷拨打

**手机号匹配孩子的规则**：
- 家长绑定手机号后，系统搜索所有学生档案中家长手机号匹配的记录
- 一个手机号可能关联多个学生（如二胎家庭）
- 一个学生可能关联多位家长（如父母双方），每位家长登录后都能看到该孩子
- 匹配不到孩子时，展示空状态引导联系机构

#### 4.3.4 常用功能

##### 报名记录

- **入口**：点击「报名记录」→ 进入报名记录页
- **内容**：按孩子分组，手风琴展开/折叠
- **每条记录展示**：
  - 课程名称 + 班级名称
  - 报名时间
  - 总课时 / 剩余课时
  - 有效期（起止日期）
  - 状态：在读 / 已结课
- **默认展开第一个孩子，其余折叠**

##### 请假申请

- **入口**：点击「请假申请」→ 进入请假管理页
- **列表**：
  - 按时间倒序展示所有请假申请
  - 每条展示：孩子姓名 + 请假日期 + 类型 + 状态（待确认/已通过/已驳回）
  - 已驳回展示驳回原因
- **发起请假**（底部悬浮按钮「+ 请假申请」）：
  - 步骤 1：选择孩子（多孩时）
  - 步骤 2：选择日期范围（单日或日期区间）
  - 步骤 3：选择请假类型（事假/病假/其他）
  - 步骤 4：填写原因（文本框，必填）
  - 提交 → 自动生成考勤请假记录 → 通知对应教师/运营主管确认
- **审批流程**：教师先确认 → 运营主管终审（或教师直接确认，取决于机构配置）

##### 考勤记录

- **入口**：点击「考勤记录」→ 进入考勤记录页
- **内容**：按孩子分组，按月份筛选
- **每条记录展示**：
  - 日期 + 课程名称 + 班级名称
  - 考勤状态：到校 / 迟到 / 缺勤 / 请假
  - 签到时间（到校/迟到时有）
- **筛选**：顶部月份选择器，默认当月
- **只读**，不可修改

#### 4.3.5 [P2] 延展功能

> **标注 P2**：以下两个功能在 P0/P1 阶段仅 PC 管理后台可用，小程序端推迟到后续迭代版本实现。页面以「即将上线」占位，或通过灰度开关控制可见性。

##### [P2] 积分兑换（N04 积分商城）

- **入口**：点击「积分兑换」→ 进入积分商城页
- **页面结构**：
  - 顶部：当前积分余额（全体孩子合计）+ 积分获取规则入口（弹窗说明）
  - 礼品列表：卡片网格，每张卡片展示礼品图片 + 名称 + 所需积分 + 库存余量
  - 点击礼品 → 进入礼品详情 → 确认兑换（扣减积分 + 生成兑换记录）
- **兑换记录**：子页面，按时间倒序展示，每条记录包含礼品名称 + 兑换时间 + 消耗积分 + 状态（待发放/已发放）
- **积分获取方式**（自动累积，无需家长操作）：
  - 签到到校：+5 积分/次
  - 教师评价学生（教评学）：+3 积分/次
  - 家长提交学评教：+2 积分/次
- **数据来源**：PC 管理后台 N04 积分商城模块配置礼品后同步到小程序

##### [P2] 学评教提交（N05 家校沟通 → 学评教）

- **入口**：点击「学评教」→ 进入学评教列表页
- **定位**：学生/家长对教师的课堂教学进行评价反馈，形成教评学 ↔ 学评教双向闭环
- **待评列表**：按时间倒序展示已完成但未评价的课次
  - 每项：日期 + 时间段 + 课程名称 + 教师姓名 + 状态（待评/已评）
  - 点击进入评价页
- **评价页**：
  - 课程信息（日期/课程/教师）
  - 星级评分（1-5 星）：
    - 教学态度
    - 课堂氛围
    - 知识讲解
    - 互动反馈
    - 综合评分
  - 快捷标签（多选）：「生动有趣」「讲解清晰」「耐心负责」「因材施教」「有待改进」等
  - 文字留言（可选，文本框，最多 500 字）
  - 是否匿名（开关，默认关闭——实名评价）
  - 底部「提交评价」按钮
- **已评列表**：查看已提交的评价内容
- **评价规则**：
  - 同一课次只能评价一次，提交后不可修改
  - 匿名评价时，教师端和 PC 后台均不显示评价人身份
  - 评价数据汇总到 PC 管理后台 N05 学评教模块

## 5. 教师端页面设计

### 5.1 课表 Tab

**定位**：查看自己的排课安排，支持月视图和周视图切换。

#### 主页面

- 顶部视图切换：「月视图」/「周视图」tab 切换
- 周视图：
  - 星期横轴（一～日），顶部周选择器：← 上一周 | 日期范围 | 下一周 →，今天一键回到本周
  - 每天列出当天的课时卡片：时间段 / 课程名称 + 班级名 / 教室位置 / 学生人数
  - 无课日显示「今日无课」
- 月视图：
  - 日历网格，有课日期显示圆点标记
  - 点击日期展开当日课表卡片列表
- 筛选：顶部筛选栏，按班级或课程过滤

#### 交互

- 点击课时卡片 → 进入该节课详情（学生名单 + 课程信息）
- 已过日期卡片置灰只读，今天和未来可操作
- 左右滑动切换周/月

---

### 5.2 签到 Tab（N07 考勤管理）

**定位**：选择当日课程，批量勾选到校学生。无地理位置限制。

#### 步骤 1：课程选择

- 显示教师当天所有排课列表（从排课数据读取）
- 每项：时间段 + 课程名 + 班级名 + 应到人数 + 已签/未签状态
- 已签到的课标注「已签到 ✓」
- 点击进入该课次的批量签到页

#### 步骤 2：批量签到

- 顶部信息栏：课程信息 + 应到/已签人数（如「已签 8/12」）
- 学生列表：
  - 默认全选所有学生
  - 每个学生一行：姓名 + 默认状态「到校」
  - 点击可切换状态：到校 → 迟到 → 缺勤
  - 已请假学生自动标记「请假」并锁定（不可修改），灰色背景区分
- 底部「确认签到」按钮
- 确认后弹出二次确认：「共 12 人，到校 10 人，迟到 1 人，缺勤 0 人，请假 1 人，确认提交？」

#### 步骤 3：签到结果

- 提交成功后展示汇总结果卡片
- 系统自动触发微信订阅消息推送对应家长
- 列表页返回时该课次标注「已签到」

### 5.3 教学 Tab（N05 家校沟通）

**结构**：顶部子导航切换「评价」和「作业」两个模块。

#### 5.3.1 评价（教评学）

**定位**：教师课后对课堂和学生个人进行评价，支持暂存草稿。

**步骤 1：选择课程**
- 近期已上课的排课列表（按日期倒序）
- 每项：日期 + 时间段 + 课程名 + 班级名 + 应到人数
- 状态标注：已评 / 待评 / 草稿
- 点击进入评价页

**步骤 2：课堂评价填写**
- 课堂总结：整体评论文本框（教学内容、课堂氛围等，必填）
- 学生个人评价列表：
  - 星级评分（1-5 星，点击打星，维度与 PC 端保持一致）
  - 文字评语（文本框，可跳过，最多 200 字）
  - 仅展示已签到学生（缺勤/请假学生不显示评价入口）
- 支持暂存草稿，后续继续编辑再提交
- 底部「提交评价」按钮

#### 5.3.2 作业（课后作业）

**定位**：教师课后布置作业，支持文字 + 图片 + 文件附件。

**作业列表**
- 已布置的作业按日期倒序
- 每项：日期 + 课程名 + 班级名 + 内容摘要（前 30 字）
- 点击展开查看完整详情

**布置作业页**
- 选择关联课程/班级（从自己教授班级中选择）
- 文字描述（文本框，必填）
- 上传图片（相册/拍照，最多 9 张）
- 上传文件（PDF/Word 等，单个不超过 10MB）
- 底部「发布」按钮
- 发布后触发微信订阅消息推送对应家长

**入口**：作业列表底部悬浮按钮「+ 布置作业」

## 8. 小程序技术设计

### 8.1 开发框架

| 选项 | 选择 | 理由 |
|------|:----:|------|
| 原生微信小程序 | — | 开发体验一般，跨端能力弱 |
| **uni-app** | ✅ | 与 PC 端共享 Vue 技术栈，一套代码多端发布，社区成熟 |
| Taro | — | React 技术栈，与项目 Vue 技术栈不统一 |

**最终选择**：uni-app（Vue 3 版本），与 PC 管理后台共享 Vue 生态和组件设计思路。

### 8.2 登录认证流程

```
小程序启动
  │
  ├─ 检查本地 token
  │   ├─ 有效 → 按角色进入对应首页
  │   └─ 无效/过期
  │       ├─ wx.login() 获取 code
  │       ├─ POST /api/v1/auth/wechat-login { code }
  │       │   ├─ 200 → 存 token → 进入首页
  │       │   └─ 401 → 未绑定 → 显示登录页
  │       └─ 用户点击授权 → getPhoneNumber → POST /api/v1/auth/wechat-bind
  │           ├─ 200 → 存 token → 进入首页
  │           └─ 401 → 手机号未关联 → 联系机构
```

### 8.3 微信订阅消息模板

> P0 阶段优先接入，P1 阶段完善模板库。

| 模板类型 | 触发场景 | 接收角色 | 模板参数 |
|----------|----------|:------:|----------|
| 签到通知 | 教师批量签到确认 | 家长 | 孩子姓名、签到时间、考勤状态、课程名称 |
| 课堂评价通知 | 教师发布教评学 | 家长 | 孩子姓名、课程名称、评价时间 |
| 作业通知 | 教师发布作业 | 家长 | 孩子姓名、课程名称、作业摘要 |
| 成绩通知 | 教师录入成绩 | 家长 | 孩子姓名、课程名称、成绩分数 |
| 请假审批结果 | 请假申请审批 | 家长/教师 | 请假类型、日期、审批结果 |
| 调课通知 | 排课变更 | 家长/教师 | 课程名称、原时间、新时间 |
| [P2] 兑换通知 | 积分兑换状态变更 | 家长 | 礼品名称、兑换时间、状态 |

**订阅授权策略**：
- 用户首次进入相关功能时弹窗引导订阅
- 一次订阅仅对一次推送有效（微信限制）
- 可在通知设置中关闭，关闭后不再引导订阅
- 后端记录订阅次数和授权状态

### 8.4 角色路由分发逻辑

```
获取用户角色 (JWT payload)
  │
  ├─ role = PARENT → 家长端（3 Tabs：首页/消息/我的）
  │    默认首页 → Tab 1（首页动态）
  │
  └─ role = TEACHER → 教师端（4 Tabs：课表/签到/教学/我的）
       默认首页 → Tab 1（课表）
```

- 路由分发在 `App.vue` 的 `onLaunch` 中完成
- 使用 `uni.switchTab` 跳转到对应角色的首页
- 无匹配角色 → 显示「暂无权限，请联系管理员」

### 8.6 [P2] 灰度开关设计

针对 P2 延展功能，小程序端通过后端配置接口控制功能可见性：

```json
{
  "features": {
    "parent.points": false,
    "parent.evaluation": false
  }
}
```

- 小程序启动时请求 `/api/v1/config/features` 获取功能开关
- P2 功能未开启时，菜单项显示「即将上线」角标，点击 toast 提示
- P0/P1 功能默认开启，不受开关影响

### 8.7 性能与体验要求

| 指标 | 目标值 | 说明 |
|------|:------:|------|
| 首页渲染时间 | < 2s | 包含动态列表首屏加载 |
| 签到提交响应 | < 1s | 批量签到接口需优化 |
| Tab 切换 | < 300ms | 已加载页面缓存，避免重复请求 |
| 图片加载 | 懒加载 + WebP | 列表图片使用缩略图，详情用原图 |
| 离线缓存 | 动态列表 | 首页动态缓存最近 20 条，无网时可浏览 |
