# N02 学员管理

> **模块编码**：N02 | **优先级**：P0 | **访问角色**：运营/校长
> **后端模块**：`edu-module-student` + `edu-module-prospect` [NEW]
> **菜单位置**：顶级菜单（高频使用）
> **权限码前缀**：`student:*` / `prospect:*`

---

## 1. 模块概述

学员管理是教育机构日常运营中最高频使用的模块之一，覆盖学员全生命周期管理：从意向获取、正式入学、课时消耗、结业归档到家长账号关联。

### 1.1 子页面清单

| 序号 | 路由 | 页面名称 | 来源 | 说明 |
|:----:|------|----------|:----:|------|
| N02.1 | `/student/enrolled` | 在学学员 | M3 迁移 | 正式在学学员档案管理，增删改查+多选操作+结业操作 |
| N02.2 | `/student/prospect` | 意向学员 | **全新** | 意向线索池管理，跟进记录时间线，转为在学学员 |
| N02.3 | `/student/completed` | 结业学员 | **全新** | 已结业学员档案归档，只读视图，支持重新激活 |
| N02.4 | `/student/parent-account` | 家长账号 | **全新** | 家长账号统一管理，启用/禁用，解绑学生关联 |
| N02.5 | `/student/hours-summary` | 课时汇总 | M3 增强 | 按学生×课程维度的课时汇总，展开课时变动明细日志 |

### 1.2 模块依赖关系

```
N02 学员管理
  ├── 被 N06.1 款项管理引用 ── 报名时选择学员/意向学员下拉搜索
  ├── 被 N07 考勤管理引用 ── 签到消费/请假返还触发课时变动记录写入
  ├── 被 N03.2 排课计划引用 ── 添加学员到班级时搜索+校验
  ├── 被 N05 家校沟通引用 ── 查看学生成绩/评价时检索学生信息
  ├── 被 N01 工作台引用 ── 学员总数统计卡片
  └── 被小程序家长端引用 ── 家长通过 sys_user → edu_student_parent 查看关联学生
```

### 2.2 搜索栏

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 姓名 | 文本输入 | 空 | 模糊匹配学员姓名 |
| 电话 | 文本输入 | 空 | 模糊匹配学员手机号或家长手机号 |
| 年级 | 下拉单选 | 全部 | 学前 / 小学一年级 ~ 高中三年级 / 其他，见 §7.1 年级枚举 |
| 状态 | 下拉单选 | 全部 | 全部 / 在读 / 停课 / 结业 / 流失 |
| 顾问 | 下拉单选 | 全部 | 可选顾问（教师角色用户），数据来源 `GET /api/v1/teacher/simple?role=consultant` |

**按钮**：

| 按钮 | 行为 |
|------|------|
| 搜索 | 重置到第 1 页 → 调用 `GET /api/v1/student/enrolled/list` |
| 重置 | 清空搜索条件 → 重新加载 |

**竞态保护**：搜索按钮触发，使用竞态序号模式。

### 2.3 工具栏

| 按钮 | 权限码 | 说明 |
|------|--------|------|
| + 新增学员 | `student:enrolled:add` | 打开新增学员弹窗（§2.6） |
| 批量操作▾ | — | 下拉菜单（多选生效，见 §2.9） |
| 导入 | `student:enrolled:import` | 打开导入弹窗（§2.8） |
| 导出 | `student:enrolled:export` | 以当前搜索条件导出全部匹配数据（不分页），浏览器下载 Excel |

> 学员管理不提供「批量删除」按钮，删除操作限制在行内逐个操作，避免误删。

### 2.4 数据表格

#### 2.4.1 列定义

| 列 | 宽度 | 对齐 | 说明 |
|------|:----:|:----:|------|
| 多选 | 40px | 中 | 复选框，用于批量操作（§2.9） |
| 序号 | 60px | 中 | 自动编号（分页连续） |
| 学员姓名 | 100px | 左 | `name`，空则显示"--" |
| 家长姓名 | 90px | 左 | 取排序第一的家长姓名，多个家长显示 `{首位姓名} +{N-1}` |
| 亲属关系 | 80px | 中 | 取排序第一的家长关系，显示中文（父亲/母亲/…） |
| 联系电话 | 130px | 左 | 脱敏展示：`138****5678`，优先展示学员手机号，学员手机号为空则展示首选家长手机号 |
| 年级 | 90px | 中 | `grade` 的中文名称 |
| 顾问 | 80px | 左 | 关联顾问姓名（来自报名记录中的 `consultant_id`），无则显示"--" |
| 性别 | 60px | 中 | 男 / 女 |
| 年龄 | 60px | 中 | 根据出生日期计算周岁，未填写则显示"--" |
| 状态 | 90px | 中 | 见 §2.4.2 状态标签 |
| 报班数 | 70px | 中 | 在读班级数量，点击数字可跳转报班记录抽屉（如果 >=1） |

| 评分次数 | 80px | 中 | 累计被评价次数（来自 N05.2 教评学），点击数字可跳转评价记录 |

| 操作 | 240px | 中 | 按钮组（见 §2.5） |

> **列宽说明**：表格总宽度约 1800px+，支持水平滚动。前 5 列（序号、学员姓名、家长姓名、亲属关系、联系电话）固定在左侧，操作列固定在右侧。中间列可自由滚动。

#### 2.4.2 状态标签

| 状态值 | 标签颜色 | 文案 | 说明 |
|--------|:--------:|------|------|
| `enrolled` | green | 在读 | 正常在读学员 |
| `suspended` | orange | 停课 | 暂停上课，剩余课时保留 |
| `completed` | blue | 结业 | 所有课程已结业，课时耗尽关闭 |
| `lost` | red | 流失 | 长期未到校、主动退学等 |

#### 2.4.3 排序

默认按 `create_time DESC` 排序。支持点击「最近到校」列头排序（升/降切换）。支持点击「剩余课时」列头排序。

#### 2.4.4 手机号脱敏

前端统一处理：`mobile.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2')`。导出时显示完整手机号（需 `student:enrolled:export` 权限，后端控制）。

### 2.6 新增/编辑学员弹窗

#### 2.6.1 触发

- 新增：工具栏「+ 新增学员」

#### 2.6.2 弹窗规格

- 宽度：750px（含家长子表格）
- 高度：自适应，最大 80vh 内部滚动
- 标题：「新增学员」/「编辑学员」

#### 2.6.3 基本字段

| 字段 | 类型 | 必填 | 新增时 | 编辑时 | 校验规则 |
|------|------|:----:|:------:|:------:|----------|
| 姓名 | 文本 | 是 | 显示 | 显示 | 1-20 字符 |
| 性别 | 单选组 | 是 | 显示 | 显示 | 男 / 女 |
| 出生日期 | 日期选择 | 否 | 显示 | 显示 | 用于计算年龄，可选 |
| 年级 | 下拉单选 | 是 | 显示 | 显示 | 见 §7.1 年级枚举 |
| 学校 | 文本 | 否 | 显示 | 显示 | 0-50 字符 |
| 手机号 | 文本 | 是 | 显示 | 显示 | 11 位数字，1 开头。失焦异步校验唯一性（编辑时排除自身） |
| 顾问 | 下拉单选 | 否 | 显示 | 显示 | 远程搜索教师列表（role=consultant），可选 |
| 标签 | 标签输入 | 否 | 显示 | 显示 | 自由输入 + 回车添加，最多 5 个标签，每标签最长 10 字符 |
| 来源渠道 | 下拉单选 | 否 | 显示 | 显示 | 地推 / 转介绍 / 线上 / 其他（可通过 N08 系统配置管理） |
| 备注 | 文本域 | 否 | 显示 | 显示 | 0-500 字符 |
| 状态 | 下拉单选 | — | **不显示** | 显示 | 仅编辑时显示：在读 / 停课 / 流失。新增默认=在读 |

**添加/编辑家长（行内编辑）**：

|------|------|:----:|------|

#### 2.6.6 交互

| 操作 | 行为 |
|------|------|
| 打开（新增） | 空表单，默认性别"男"，年级默认"小学一年级"，家长子表格为空 |
| 打开（编辑） | 调用 `GET /api/v1/student/{id}` → 填充表单 + 加载家长列表 |
| 确认 | 前端校验 → 提交 API → 成功 → toast + 关闭弹窗 + 刷新列表 |
| 取消 | 有修改 → 确认"放弃修改？"；无修改 → 直接关闭 |

#### 2.6.7 状态处理

| 状态 | 表现 |
|------|------|
| 加载中（编辑） | 弹窗内骨架屏（学生区 + 家长区各一个灰色块） |
| 加载失败（编辑） | "加载学员信息失败" + 「重试」 |
| 手机号唯一性校验中 | 输入框右侧 loading 图标 |
| 手机号已被占用 | 红色错误"该手机号已被其他学员使用"，不可提交 |
| 提交中 | 确认按钮 loading，"保存中…" |
| 提交失败 | 保留弹窗 + 错误提示（后端返回的 msg） |
| 提交成功 | toast "保存成功" + 关闭弹窗 + 刷新列表 |

### 2.8 导入/导出

**导入流程**：

1. 点击「下载模板」→ `GET /api/v1/student/template` → 浏览器下载 Excel
2. 点击「导入」→ 打开导入弹窗（上传区域 + 下载模板链接）
3. 上传文件 → 格式校验（仅允许 `.xlsx` `.xls`，最大 10MB） → 调 `POST /api/v1/student/import`
4. 返回结果 → 弹窗展示导入结果（成功 N 条 / 失败 M 条 + 失败原因列表）

**导出**：点击「导出」→ 以当前搜索条件（不分页）调 `GET /api/v1/student/export` → 浏览器下载 Excel。导出列：姓名、性别、出生日期、年级、学校、手机号（完整号码）、顾问、来源渠道、状态、报班数、剩余课时、标签、备注、家长姓名、家长关系、家长手机号。

### 2.9 多选操作

勾选表格行左侧复选框后，表格底部出现批量操作栏：

| 按钮 | 权限码 | 行为 |
|------|--------|------|
| 批量结业 | `student:enrolled:edit` | 对已选学员执行结业操作（仅对「所有报班已关闭且剩余课时=0」的学员生效，不满足条件的跳过并提示） |
| 批量停课 | `student:enrolled:edit` | 对已选「在读」状态学员批量停课 |
| 批量更改顾问 | `student:enrolled:edit` | 弹出顾问选择对话框，将已选学员的顾问统一更改为指定顾问 |

### 2.10 删除保护规则

删除前前端校验（后端同时校验）：

| 条件 | 行为 |
|------|------|
| 有在读班级（报班记录状态=在读） | 禁止删除："该学员还有 {N} 个在读班级，请先办理退班/结课后再删除" |
| 有剩余课时（>0） | 禁止删除："该学员还有 {N} 课时未消耗，请先办理退费后再删除" |
| 无在读班级且无剩余课时 | 二次确认："确认删除学员「{姓名}」？删除后不可恢复。关联的家长信息、课时变动记录将保留。" |

> **重要**：删除学员时不级联删除家长 sys_user（可能关联其他学生），不删除课时变动记录（财务审计需求）。学员记录本身使用逻辑删除 `is_deleted`。

#### 3.7.3 转化后端逻辑

调用 `POST /api/v1/prospect/{id}/convert`：

1. 校验意向学员状态（不可重复转化）
2. 在事务中：
   - 创建 `edu_student` 记录（继承 name, gender, grade, birth_date, mobile, consultant_id, source）
   - 创建 `edu_student_parent` 记录（继承 parent_name, relation, mobile）
   - 自动创建/关联家长 sys_user（同 §7.5）
   - 意向学员 `edu_prospect.status` 更新为 `converted`，记录 `converted_student_id`
   - 复制意向备注到在学学员备注（前缀"[意向转化] "）
3. 返回新创建的 `student_id`
4. 若勾选「立即创建报名记录」，前端携带 `student_id` 跳转至 N06.1 款项管理-新增报名页面


### 5.6 业务规则

- 解绑 = 删除 `edu_student_parent` 关联记录（逻辑删除）
- 不解绑家长 sys_user（该家长可能还关联其他学生）

## 7. 全局业务规则

### 7.1 年级枚举

```
学前, 小学一年级, 小学二年级, 小学三年级, 小学四年级, 小学五年级, 小学六年级,
初中一年级, 初中二年级, 初中三年级,
高中一年级, 高中二年级, 高中三年级,
其他
```

后端存储为 `VARCHAR(20)` 代码（如 `PRESCHOOL`, `GRADE_1`, `GRADE_7`, `GRADE_10`），前端展示中文。

### 7.2 学员状态流转

```
                      ┌──────────┐
            ┌────────>│  在读    │─────────┐
            │         │ enrolled │         │
            │         └─────┬────┘         │
            │               │              │
      ┌─────┴─────┐   ┌─────▼─────┐   ┌───▼──────┐
      │  停课     │   │  结业     │   │  流失    │
      │ suspended │   │ completed │   │  lost    │
      └─────┬─────┘   └─────┬─────┘   └──────────┘
            │               │
            └───────────────┘
            (手动恢复/重新激活)
```

| 从 | 到 | 触发条件 | 手动/自动 |
|------|------|------|:--------:|
| — | 在读 | 新增学员 / 意向转化 | 自动 |
| 在读 | 停课 | 管理员主动操作（如长期请假/暂停） | 手动 |
| 在读 | 结业 | 所有报班记录状态=已结课，且剩余课时=0 | 自动/手动 |
| 在读 | 流失 | 管理员标记（连续 N 天未到校可配置触发） | 手动/可配置自动 |
| 停课 | 在读 | 管理员恢复 | 手动 |
| 结业 | 在读 | 重新激活（手动）或新报名时自动激活 | 手动/自动 |
| 流失 | 在读 | 重新报名（产生新报班记录）后自动恢复 | 自动 |

**状态联动规则**：
- 学生状态=「结业」或「流失」时，不可新增报班记录（N06.1 款项管理需校验）。
- 学生状态从「结业」/「流失」变更为「在读」时，需有新的报班记录。

### 7.3 意向学员 → 在学学员转化

```
意向学员 (edu_prospect)
  │
  │ 1. 管理员点击「转为在学」
  │ 2. 系统校验：状态不可为「已转化」
  │ 3. 事务内执行：
  │    a. 创建 edu_student，继承 name/gender/grade/mobile/source/consultant_id
  │    b. 创建 edu_student_parent，继承 parent_name/relation/mobile
  │    c. 自动创建/关联家长 sys_user（同 §7.5）
  │    d. edu_prospect.status = 'converted'
  │    e. edu_prospect.converted_student_id = 新 student.id
  │ 4. 可选：跳转至 N06.1 新增报名
  │
  ▼
在学学员 (edu_student, status=enrolled)
  source 字段继承自 edu_prospect.source
```

**数据继承映射**：

| 意向学员字段 | 在学学员字段 | 说明 |
|-------------|-------------|------|
| name | name | 直接继承 |
| gender | gender | 直接继承 |
| birth_date | birth_date | 直接继承 |
| grade | grade | 直接继承 |
| mobile | mobile | 直接继承 |
| consultant_id | consultant_id | 直接继承 |
| source | source | 直接继承（来源渠道可追溯至意向阶段） |
| remark | remark | 复制并添加前缀"[意向转化] " |
| parent_name | → edu_student_parent.name | 创建首条家长记录 |
| relation | → edu_student_parent.relation | 创建首条家长记录 |

### 7.4 结业规则

**自动结业条件**（定时任务每日凌晨检查）：

```
SELECT * FROM edu_student
WHERE status = 'enrolled'
  AND is_deleted = 0
  AND id NOT IN (
    SELECT DISTINCT student_id FROM edu_enrollment
    WHERE status = 'enrolled' AND is_deleted = 0
  )
  AND id IN (
    SELECT student_id FROM edu_enrollment
    WHERE status = 'closed' AND remaining_hours = 0 AND is_deleted = 0
  );
```

满足条件 → 自动将 status 更新为 `completed`，记录 `completed_at` 时间戳。

**手动结业**：管理员在 N02.1 操作列点击「结业」，系统校验条件后执行。不满足条件时按钮灰色不可点击。

**结业后约束**：
- 不可新增报班记录（需先重新激活）
- 不可参与排课
- 不可签到
- 可查看历史数据（详情抽屉）

### 7.5 家长账号自动创建与关联

**触发时机**：学员保存时（新增或编辑），对于家长子表格中新增或修改手机号的家长记录。

**处理逻辑**：

```
foreach parent in (parentAdds + parentUpdates where mobile changed):
    user = sys_user 按 mobile 查询
    if user == null:
        创建 sys_user:
            username = mobile
            real_name = parent.name
            password = 随机 16 位字符串 (BCrypt 加密)
            role = "PARENT"
            status = 0 (正常)
        edu_student_parent.user_id = 新 user.id
    else if user.role 不含 PARENT:
        为该 user 追加 PARENT 角色
        edu_student_parent.user_id = user.id
    else:
        edu_student_parent.user_id = user.id
```

**约束**：
- 删除家长时不删除对应的 sys_user（该家长可能还关联其他学生）
- 修改家长手机号时，旧的 sys_user 关联不自动清理（需管理员手动处理）
- 家长通过微信小程序首次登录时，`wx_openid` 绑定到对应的 sys_user
- 一个家长账号可关联多个学生（通过 `edu_student_parent` 多记录）

### 7.6 手机号去重规则

| 场景 | 校验规则 | 类型 |
|------|----------|:----:|
| **在学学员手机号** | 全局唯一（`is_deleted=0` 条件下）。新增时校验，编辑时排除自身 | 硬阻断 |
| **意向学员手机号** | 与在学学员手机号冲突时 → 提示但不阻断："该手机号已存在在学学员「{姓名}」，是否继续添加？"；与意向学员手机号重复时 → 同硬阻断 | 软提示 |
| **家长手机号** | 同一学生下不可重复；不同学生间可以重复 | 硬阻断/允许 |

### 7.7 来源渠道可配置

来源渠道初始默认值：地推、转介绍、线上、其他。

管理员可在 N08 系统配置中增删改来源渠道选项（配置键：`prospect_source`，类型：JSON 数组）。新增渠道后，意向学员来源下拉和新增/编辑表单中的来源选项同步更新。

### 7.8 课时变动审计

| 上游操作 | 课时变动类型 | 数量计算 | 来源模块 |
|----------|-------------|----------|----------|
| N06.1 收费确认 | 报名获得 | +(购买的课时数) | N06.1 → N02 |
| N06.1 赠课时审批 | 赠送获得 | +(赠送课时数) | N06.1 → N02 |
| N07 签到成功 | 消课扣减 | -(本次上课应扣课时) | N07 → N02 |
| N07 请假审批通过 | 请假返还 | +(已扣的课时) | N07 → N02 |
| N07 补课签到 | 补课消耗 | -(补课消耗课时) | N07 → N02 |
| N06.1 退费审批通过 | 退费扣减 | -(已退课时数) | N06.1 → N02 |

**课时变动记录不可编辑、不可删除**——所有数据由上游模块的业务操作触发写入。

> **后端约束**：`edu-module-student` 模块提供课时变动的写入 API（内部服务接口，供其他模块 Service 调用，非 Controller 端点），由 N06.1 和 N07 等模块的 Service 层调用。

**剩余课时汇总计算**：

```
学生「剩余课时」= 所有「在读」状态的报班记录中 remaining_hours 之和。
SELECT SUM(remaining_hours) FROM edu_enrollment
WHERE student_id = ? AND status = 'enrolled' AND is_deleted = 0
```

## 11. 异常边界

### 11.1 并发冲突

| 场景 | 处理策略 |
|------|----------|
| 两人同时编辑同一学员 | MVP 阶段采用"最后写入胜出"（不做版本冲突检测）。后续高频冲突时加 `version` 字段乐观锁 |
| 同一家长手机号同时关联到不同学生 | 允许（不同学生可有相同手机号的家长），sys_user 可关联多个学生 |
| 课时变动记录同时写入 | 数据库行锁 + 事务保证。`edu_student_hour_log` 只追加不修改，无并发冲突 |
| 同一意向学员被多人同时转化 | 后端校验 `status != 'converted'`，第二人提交时返回"该意向学员已被转化" |

### 11.2 数据一致性

| 场景 | 处理策略 |
|------|----------|
| 报名成功但课时变动记录写入失败 | 事务回滚。N06.1 收费确认 + 课时写入在同一事务中 |
| 签到消耗课时后剩余课时变负数 | 不允许。签到前校验 `remaining_hours >= consume_amount`，不足则阻止签到并提示"课时不足，请先续费" |
| 删除学员时家长 sys_user 残留 | 不删除家长 sys_user。家长可能关联其他学生。`edu_student_parent` 使用逻辑删除 |
| 退费金额大于剩余课时价值 | 由 N06.1 模块校验，N02 模块提供当前剩余课时供计算 |
| 意向转化后原意向记录状态未更新 | 事务内保证，`status` 更新 + `converted_student_id` 写入原子执行 |
| 体验课次数与实际排课不一致 | 由 N07 考勤/N03.2 排课模块通过 `ProspectService.incrementTrialCount()` 触发更新 |

### 11.3 边界输入

| 场景 | 处理策略 |
|------|----------|
| 姓名过长（>20字符） | 前端 maxlength 限制 + 后端校验，返回"姓名最多 20 字符" |
| 手机号格式非法 | 前端正则 `^1\d{10}$` + 后端校验，返回"手机号格式不正确" |
| 家长子表格为空（提交时） | 允许保存，学生可以不关联家长 |
| 家长超过 5 个 | 前端不硬限制，但提示"建议关联不超过 5 位家长" |
| 标签超过 5 个 | 前端限制最多 5 个，input 在已有 5 个标签后禁用 |
| 标签超过 10 字符 | 前端 maxlength + 后端校验 |
| 跟进内容超过 1000 字符 | 前端 textarea maxlength + 后端校验 |
| 意向学员备注超过 500 字符 | 前端 maxlength + 后端校验 |
| 年级非法值 | 前端下拉限定 + 后端白名单校验 |
| 来源渠道非法值 | 前端下拉 + 后端校验渠道是否在系统配置中 |
| 出生日期为未来日期 | 前端 `disableDate` 限制 + 后端校验 |

### 11.4 权限边界

| 场景 | 处理 |
|------|------|
| 无 `student:enrolled:list` 权限 | 左侧菜单不显示「学员管理」入口。直接访问 URL → 后端返回 403 → 前端跳转 403 页面 |
| 无 `student:enrolled:add` 权限 | 隐藏「新增学员」按钮 |
| 无 `student:enrolled:edit` 权限 | 隐藏「编辑」「结业」「停课」按钮，但不影响详情/报班记录/课时记录按钮（这些需要 `student:enrolled:view`） |
| 无 `student:enrolled:delete` 权限 | 隐藏「删除」按钮 |
| 无 `prospect:*` 权限 | 「意向学员」子菜单不显示 |
| 无 `student:completed:list` 权限 | 「结业学员」子菜单不显示 |
| 无 `student:parent:list` 权限 | 「家长账号」子菜单不显示 |
| 教师角色 | 不展示学员管理菜单，无任何 student/prospect 权限 |
| 家长角色 | 通过小程序端专用 API 查看关联学生信息（独立于 PC 管理端权限体系） |
