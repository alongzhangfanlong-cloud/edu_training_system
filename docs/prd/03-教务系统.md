# N03 教务系统

> **模块定位**：核心教务层（P0），合并原 M1 课程管理 + M4 班级管理 + M5 排课管理 + M11 课件资料库。是教务体系的中枢，上承课程/科目/教室基础资源，下接排课/课表/考勤/教学等业务流程。
> **后端模块**：`edu-module-course` + `edu-module-class` + `edu-module-schedule` + `edu-module-resource`
> **菜单位置**：左侧「教务系统」目录
> **访问角色**：运营/校长（全部功能）、教师（仅课程表+课件阅览）
> **优先级**：P0

---

## 1. 模块概述

### 1.1 模块价值

教务系统是教育机构日常运营的核心操作平台。本模块整合了课程体系搭建、班级组建管理、排课计划与课程表查看、教室资源调度、课件资料共享等全部教务职能，为考勤（N07）、报名（N06）、教学（N05）等下游模块提供数据基础。

#### 3.1.4.2 上课情况判定逻辑

| 条件 | 显示 | 标签颜色 |
|------|------|:--:|
| `schedule_date > today` | 未上 | 灰色 |
| `schedule_date = today` 且 `start_time > now` | 未上 | 灰色 |
| `schedule_date < today` 且有签到记录 | 已上 | 绿色 |
| `schedule_date < today` 且无签到记录 | 缺勤 | 红色（系统自动标记，表示该课未执行） |
| `schedule_date = today` 且 `end_time <= now` 且有签到 | 已上 | 绿色 |

### 3.1.5 操作列按钮

| 按钮 | 显示条件 | 权限码 | 行为 |
|------|------|--------|------|
| 停课 | 上课情况 = 未上（且状态为正常/补课） | `schedule:cancel` | 弹出停课确认弹窗 → 填写原因 → 状态变为"停课" |
| 更改时间地点 | 上课情况 = 未上（且状态为正常/补课） | `schedule:reschedule` | 弹出调课弹窗（同 M5 §6.3），支持修改日期/时间/教室 |
| 消课 | 上课情况 = 未上 且 `schedule_date <= today` | `schedule:consume` | 手动消课（用于补录无签到记录的情况），二次确认后标记为已上 |
| 详情 | 始终 | `schedule:calendar:list` | 弹出排课详情弹窗（含学生名单 + 签到明细） |

> 已过日期且已上的排课，操作列仅显示「详情」。
> 教师角色仅显示「详情」，无停课/调课/消课按钮。

### 3.1.7 消课操作

消课用于补录无签到记录但实际已上课的情况。

| 场景 | 行为 |
|------|------|
| 点击「消课」 | 弹出二次确认："确认将该排课标记为已上？消课操作不可撤销。" |
| 确认 | 调用 `PUT /api/v1/schedule/{id}/consume` → 标记该排课为已上，记录消课时间 + 操作人 |
| 消课与签到 | 消课不生成签到记录，仅改变"上课情况"状态。若后续有签到记录产生，以签到为准 |

### 3.1.8 周视图 / 月视图 / 日视图

日历视图设计继承 M5 排课管理 §5 的完整设计，此处列出关键差异：

| 项目 | M5 原设计 | N03.1 调整 |
|------|------|------|
| 周视图布局 | 7列（周一~周日），纵轴课节时段 | 不变 |
| 排课卡片内容 | 课程 + 班级 + 教师·教室 + 人数 | 额外显示：签到数/到课率（小字） |
| 颜色标记 | 按科目分色 | 不变 |
| 月视图日格 | 显示排课数量 | 额外显示：当日到课率汇总 |
| 日视图 | M5 无独立日视图 | **新增**：纵向时间轴，每30分钟一行，排课卡片跨行渲染 |
| 状态标记 | 正常/取消/调课/补课/停课/强排 | 额外标记：●已上（绿色勾）/ ○未上 |

**日视图时间轴**：纵轴 06:00~22:00，每 30 分钟一行。排课卡片按实际起止时间跨行渲染。点击排课卡片弹出详情弹窗（同 §3.1.5）。

### 3.1.9 状态处理

### 3.2.8 生成课程表（状态流转）

```
未生成 → 点击「生成课程表」
  → 执行三维冲突检测（教师-教室-班级）
  → 无冲突 → 计划状态=已生成 → 排课记录写入 edu_schedule → 课程表（N03.1）自动显示
  → 有冲突 → 弹出冲突汇总弹窗
        → 强制生成 → 冲突项 force_flag=1 → 状态=已生成
        → 跳过冲突项 → 仅无冲突的写入 → 状态=已生成
        → 取消 → 回到列表
```

**冲突检测规则**（继承 M5 §4 完整设计）：

| 维度 | 检测逻辑 |
|------|------|
| 教师冲突 | 同一教师，同一日期及时段（时间有交集），已有其他「正常/补课」状态的排课 |
| 教室冲突 | 同一教室，同一日期及时段（时间有交集），已有其他「正常/补课」状态的排课 |
| 班级冲突 | 同一班级，同一日期及时段（时间有交集），已有其他「正常/补课」状态的排课 |

时间交集判定：`start1 < end2 AND end1 > start2`。已取消/已调课/停课状态不参与冲突检测。

### 3.4.5 班级状态流转

```
                    ┌──────────┐
         手动操作    │  招生中   │  人数达到上限（自动）
    ┌──────────────►│ ENROLLING ├──────────────────────┐
    │               └─────┬────┘                      │
    │                     │                           │
    │       手动操作       │  手动操作                  │
    │                     │                           ▼
    │               ┌─────▼────┐                ┌──────────┐
    │               │  停招    │                │   已满    │
    │               │SUSPENDED │                │   FULL   │
    │               └─────┬────┘                └────┬─────┘
    │                     │                         │
    │       手动操作       │    手动操作               │ 手动操作
    │                     │                         │
    │                     ▼                         ▼
    │               ┌──────────────────────────────────┐
    │               │            结课                   │
    └───────────────│          FINISHED                │
      手动操作       └──────────────────────────────────┘
```

规则：
- "招生中" ↔ "停招"：可双向手动切换
- "招生中" → "已满"：系统自动（添加学员后 `currentCount ≥ maxCount`）
- "已满" → "招生中"：系统自动（移除学员后 `currentCount < maxCount`）或手动调大最大人数
- 所有状态 → "结课"：手动操作，终态，不可逆
- 超员（`currentCount > maxCount`）不是独立状态，是异常标记

## 9. 业务规则汇总

### 9.1 科目引用保护（§3.5.7）

```
edu_subject ──1对多── edu_course ──1对多── edu_class
```

| 规则 | 说明 |
|------|------|
| 停用 | 科目可随时停用。停用后标签栏灰显+后置；新增/编辑课程下拉不显示；已有课程不受影响 |
| 删除前置检查 | 删除前检查 `edu_course.subject_id` 引用。有引用 → 禁止删除 |
| 无引用 | 允许删除 |

### 9.2 课程引用保护（§3.3.8）

| 规则 | 说明 |
|------|------|
| 下架 | 课程可随时下架。下架后列表行变灰；新增班级下拉不显示；已有班级不受影响 |
| 删除前置检查 | 删除前检查 `edu_class.course_id` 引用。有引用 → 禁止删除 |
| 无引用 | 允许删除 |
| 已下架+无引用 | 允许删除 |

### 9.3 教室引用保护（§3.6.6）

| 规则 | 说明 |
|------|------|
| 停用 | 教室可随时停用。停用后列表行变灰；排课下拉不显示；已有排课不受影响 |
| 删除前置检查 | 删除前检查排课表 `classroom_id` 引用。有引用 → 禁止删除 |
| 无引用 | 允许删除 |

### 9.4 引用保护前端联动

| 对象 | 被引用时前端按钮状态 |
|------|------|
| 科目 | 「删除」隐藏，仅显示「编辑」「停用/启用」 |
| 课程 | 「删除」隐藏，仅显示「编辑」「上架/下架」 |
| 教室 | 「删除」隐藏，仅显示「编辑」「启用/停用」 |

> 前端通过列表接口的 `referenced` 字段（boolean）控制按钮显隐。

### 9.5 班级状态机（§3.4.5）

| 状态 | 英文 | 触发条件 |
|------|------|------|
| 招生中 | `ENROLLING` | 新建班级默认状态 |
| 已满 | `FULL` | 已报人数 ≥ 最大人数时自动变更 |
| 停招 | `SUSPENDED` | 手动操作 |
| 结课 | `FINISHED` | 手动操作，终态不可逆 |

状态流转：
- 招生中 ↔ 停招：手动双向
- 招生中 → 已满：自动；已满 → 招生中：自动（移除学员或调大容量）
- 全部 → 结课：手动，不可逆
- 超员（currentCount > maxCount）：异常标记，非独立状态

### 9.6 排课状态机（§3.2.8）

| 状态 | 说明 |
|------|------|
| 未生成 | 计划新建后默认状态 |
| 已生成 | 冲突检测通过并确认生成后 |

### 9.7 冲突检测算法（§3.2.8，继承 M5 §4）

三维独立检测：教师-教室-班级，任一维度命中即为冲突。

时间交集判定：`start1 < end2 AND end1 > start2`

排除项：已取消/已调课/停课状态的排课不参与冲突检测；编辑/调课时排除自身记录。

### 9.8 排课记录状态机

```
正常(NORMAL) / 补课(MAKEUP) ──取消──→ 已取消(CANCELLED)
正常(NORMAL) / 补课(MAKEUP) ──调课──→ 已调课(RESCHEDULED) + 新记录(NORMAL)
正常(NORMAL) / 补课(MAKEUP) ──停课──→ 停课(SUSPENDED)
```

### 9.9 课件共享范围规则（§3.7.9）

| 共享范围 | 运营主管 | 校长 |
|------|------|------|
| 公开 | 全部可见/可下载/可管理 | 全部可见/可下载 |
| 私有 | 全部可见/可下载/可管理 | 全部可见/可下载 |

## 13. 异常边界

### 13.1 重复名称/编号

| 场景 | 前端行为 | 后端行为 |
|------|------|------|
| 科目名称重复 | — | 返回 400 "科目名称已存在" |
| 课程编号重复 | 失焦异步校验，红色提示"该编号已被使用"，阻止提交 | 返回 400 "课程编号已存在" |
| 同科目下课程名称重复 | 失焦异步校验，红色提示"该科目下已有同名课程"，阻止提交 | 返回 400 "该科目下课程名称已存在" |
| 教室名称重复 | 失焦异步校验，红色提示"该教室名称已存在"，阻止提交 | 返回 400 "教室名称已存在" |

### 13.2 引用删除拦截

| 场景 | 前端行为 | 后端返回 |
|------|------|------|
| 删除被引用的科目 | 「删除」按钮已隐藏 | 绕过前端 → 400 "该科目下已有{N}门课程，不可删除，仅可停用" |
| 删除被引用的课程 | 「删除」按钮已隐藏 | 绕过 → 400 "该课程已被{N}个班级引用，不可删除，仅可下架" |
| 删除被引用的教室 | 「删除」按钮已隐藏 | 绕过 → 400 "该教室已被{N}条排课记录引用，不可删除，仅可停用" |
| 删除有学员的班级 | 「删除」按钮校验 | 返回 422 "班级下有{N}名在讀学员，不可删除" |
| 删除已生成的排课计划 | 「删除」按钮隐藏 | 返回 400 "已生成的排课计划不可删除" |

### 13.3 并发冲突

| 场景 | 处理策略 |
|------|------|
| 多人同时添加学员到同一班级 | 数据库行锁 `SELECT ... FOR UPDATE`，先到先得；后到达返回 422 |
| 多人同时移除学员 | 允许并发，后操作的返回 404 |
| 多人同时编辑班级 | 乐观锁（`update_time` 版本比较），冲突提示刷新 |
| 同一排课被同时取消和调课 | 先到达的请求正常处理，后到的返回"排课状态已变更，请刷新" |
| 编辑的科目/课程/教室已被他人删除 | 提交后返回 404 → toast "该数据已被删除，请刷新列表" |

### 13.4 日期边界

| 场景 | 处理方式 |
|------|------|
| 选择已过日期排课 | 日期选择器 `disabledDate` 禁止选择，提交时二次校验 |
| 停课/调课已过日期的排课 | 操作按钮灰显 + tooltip "已过上课日期，不可操作" |
| 批量排课起止日期倒挂 | 表单校验："结束日期不可早于起始日期" |
| 批量排课跨度超 180 天 | 表单校验："日期跨度不可超过 180 天" |

### 13.5 其他边界

| 场景 | 行为 |
|------|------|
| 课程单价输入负数 | 前端 `min=0` 阻止；后端校验返回 400 |
| 教室容纳人数为 0 | 前端 `min=1` 阻止；后端校验返回 400 |
| 设施标签超 10 个 | 前端输入框 disabled + 提示；后端校验返回 400 |
| 文件超 50MB | 前端选择时拦截；后端 multipart 配置 `max-file-size: 50MB` |
| 不支持的课件格式 | 前端选择时拦截 + toast；后端 MIME 白名单二次校验 |
| 上传中断网 | 进度条停止 → toast + 恢复确认按钮 |
| 一对一课程最大人数被修改 | 后端校验返回 422 "一对一课程最大人数固定为 1" |
| 班级最大人数调至小于当前人数 | 后端校验返回 422 "最大人数不可小于当前已报人数 {N}" |

### 13.6 数据一致性保障

| 保障项 | 机制 |
|------|------|
| `current_count` 与实际学员数一致 | 添加/移除学员时事务内更新；定期任务校验 |
| 状态与人数一致 | 添加学员后自动触发 `FULL`；移除学员后自动恢复 `ENROLLING` |
| 唯一约束 | `class_student` 表 `(class_id, student_id)` 唯一索引 |
| 教师-科目匹配 | 添加/编辑班级时后端校验 |
| 课件记录与物理文件一致 | 先上传文件后创建记录的二阶段模式 |
