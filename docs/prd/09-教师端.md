# N09 教师端

> **编码**：N09 | **菜单名**：教师端 | **优先级**：P0
> **访问角色**：教师（专属，校长/运营主管不可见此菜单）
> **后端模块**：`edu-module-teacher-dashboard` [NEW] + `edu-module-teaching` + `edu-module-resource` + `edu-module-schedule`（多模块复用）
> **菜单结构**：扁平4项，无子菜单
> **版本**：v1.0 | **日期**：2026-07-14

---

## 1. 模块概述与定位

### 1.1 一句话描述

教师端是教师登录 PC 管理后台后的专属工作空间，聚合了教师日常所需的**今日课表与签到、课后作业布置与批改、课件上传与共享、完整课表查看**四大核心能力。

### 1.2 核心定位

| 维度 | 说明 |
|------|------|
| **使用者** | 全体授课教师 |
| **使用频率** | 每天多次（登录即见工作台，课后布置作业，课前查看课表） |
| **核心价值** | "今天上什么课、有哪些待办、课后要做什么" |
| **不做的事** | 不暴露运营全局数据（营收、招生），不可修改排课，不可查看其他教师的未公开课件 |

### 1.3 与主模块的关系

教师端不是独立的功能模块，而是**主模块的教师视角过滤视图**——教师端各页面复用主模块的后端能力，但在数据范围、操作权限上做教师维度的收敛。

```
N09 教师端
  ├── N09.1 教师工作台 → [NEW] 全新页面，复用 edu-module-dashboard 设计模式
  ├── N09.2 课后作业   → 复用 N05.1 作业管理，过滤：仅当前教师发布
  ├── N09.3 课件共享   → 复用 N03.7 课件资料库，过滤：公开课件 + 教师私有课件
  └── N09.4 我的课表   → 复用 N03.1 课程表视图，过滤：仅当前教师
```

### 1.4 教师权限范围（核心约束）

以下规则贯穿教师端全部页面，是教师端设计的根基：

| 规则编号 | 规则内容 |
|:--:|------|
| **TR01** | 教师仅能看到自己所教班级的排课数据（通过 `edu_schedule.teacher_id` 过滤） |
| **TR02** | 教师仅能看到自己发布的作业（通过 `edu_homework.teacher_id` 过滤） |
| **TR03** | 教师仅能编辑/删除自己发布的作业、自己上传的课件 |
| **TR04** | 教师可浏览其他教师公开的课件（只读+下载），不可查看他人私有课件 |
| **TR05** | 教师不可进行排课、调课、取消操作（课表为只读视图） |
| **TR06** | 教师可对班级进行签到操作（考勤模块的教师权限沿用，见 N07） |
| **TR07** | 教师不可查看营收数据、学员详情（除所教班级学生名单外）、退费、课酬 |
| **TR08** | 教师看到的统计数字均为个人维度（"今日我有几节课"而非"全机构今日几节课"） |

### 1.5 菜单结构

```
📊 工作台                    ← N09.1 [NEW]（教师登录默认首页）
📝 课后作业                  ← N09.2（作业布置/编辑/查看）
📂 课件共享                  ← N09.3（课件上传/浏览/下载）
📅 我的课表                  ← N09.4（只读课表视图）
```

教师登录后默认跳转到「工作台」。

| 2 | 今日待签到班级数 | 今日排课中尚未完成全部签到的班级数（至少 1 人未签到） | 跳转 N07 考勤管理（签到页面，筛选当前教师+今日） |

#### 2.2.3 我的今日课表

以卡片式时间线展示今日所有排课，按开始时间升序排列。每条排课卡片包含：

| 字段 | 说明 |
|------|------|
| 时间 | `HH:mm ~ HH:mm`，进行中课程时间标签为绿色背景 |
| 课程名称 | 关联课程名 |
| 班级名称 | 关联班级名 + 应到人数 |
| 教室名称 | 关联教室名 |
| 签到状态 | 见下方状态表 |
| 签到操作按钮 | 见下方交互行为 |

**课表卡片状态与视觉标记**：

| 课程状态 | 判定条件 | 视觉标记 |
|----------|---------|---------|
| 未开始 | `start_time > now` | 默认样式，灰色时间标签 |
| 进行中 | `start_time <= now <= end_time` | 左侧绿色竖条（4px），时间标签绿色背景，标题旁 Badge "进行中" |
| 已结束 | `end_time < now` | 整体半透明（opacity: 0.6），时间标签灰色 |

**签到状态与操作按钮**：

| 签到状态 | 判定条件 | 操作按钮 |
|----------|---------|---------|
| 未签到 | 排课已开始/进行中/已结束，但无任何签到记录 | 「可签到」按钮（蓝色 `type="primary"`） |
| 签到中 | 部分学生已签到，部分未签到 | 显示 "已签到 N/M" + 「签到管理」按钮 |
| 已签到 | 全部应到学生已完成签到 | 绿色对勾 ✅ + "已全部签到"，按钮不可用（灰色） |
| 未开始 | 排课尚未开始 | 不显示签到按钮，显示"--" |

**学生人数展示**：每张卡片显示 "应到 N 人"，点击可展开学生名单（同 N01 工作台模式），已签到学生绿色标签边框，未签到学生灰色标签。展开数据从 `GET /api/v1/teacher/dashboard/schedule/{scheduleId}/students` 获取。

#### 2.2.4 待办区

| 序号 | 待办项 | 数据来源 | 计数逻辑 | 跳转目标 |
|:--:|------|---------|---------|---------|

### 2.4 状态处理

| 状态 | 表现 |
|------|------|
| 首次加载 | 欢迎区立即渲染（从 Pinia userStore 取用户信息）；统计卡片显示骨架屏（灰色矩形）；今日课表显示 4 条骨架卡片；待办区显示 2 条骨架条 |
| 今日无课程 | 统计卡片"今日课程数"显示 0；课表区域显示空状态 "📅 今日无课程安排，好好休息吧 ☕" |
| 今日无待办 | 待办区显示 "✓ 暂无待办事项，今天一切顺利！" |
| 今日无待签到 | 统计卡片"待签到班级数"显示 0，绿色数字 |
| 单卡片加载失败 | 该卡片显示 "--" + "加载失败" 红色文字 + 「重试」链接，不影响其他卡片 |
| 课表加载失败 | 课表区域显示 "课表加载失败" + 「重试」按钮 |
| 全部加载失败 | 页面中间显示 "网络连接失败，请检查网络后重试" + 「重试」按钮，保留欢迎区 |

### 2.5 数据刷新策略

| 时机 | 策略 |
|------|------|
| 登录后首次进入 | 全量加载（4 个 API 并发请求） |
| 页面切换回来（Tab 切回） | 全量刷新 |
| 定时自动刷新 | 每 5 分钟静默刷新统计卡片 + 待办区数字，不动课表展开状态 |
| 手动刷新 | 页面右上角刷新按钮（圆形图标），全量刷新 |
| 点击穿透后返回 | 保留数据不刷新 |

### 2.6 后端实现要点

后端新建模块 `edu-module-teacher-dashboard`，职责仅为教师工作台的数据聚合。

**Service 层跨模块调用约定**：
- 教师工作台不直接访问其他模块的 Mapper
- 通过各业务模块对外暴露的 Feign 接口或 Service 接口获取数据
- 聚合编排在工作台 Service 中完成

**关键查询逻辑**：
- 所有排课查询：`WHERE teacher_id = #{currentTeacherId}` + 日期过滤
- 待签到班级：按排课分组，检查签到表 `edu_attendance` 是否全量覆盖该排课关联班级的学生
- 待评价学生：按排课维度，查询已上课但 `edu_evaluation_student` 中无对应记录的学生

#### 3.3.4 查看作业详情

### 4.3 交互行为

#### 4.3.1 上传课件

| 课件名称 | 文本输入 | ✅ | 1-50 字符，不含 `<>"/\|?*` | |

| 年级 | 下拉单选 | ✅ | 一年级~高三 | |
| 类型 | 下拉单选 | ✅ | 课件文档 / 教学PPT / 练习资料 / 其他 | |
| 上传文件 | 文件上传 | ✅ | 支持 PDF/Word/PPT/图片/压缩包，单文件 ≤ 50MB | |

上传流程：
1. 前端校验（名称、分类、文件格式、大小）
2. 确认按钮 loading "上传中…"，进度条展示
3. 先上传文件：`POST /api/v1/files/upload`（FormData，获取 fileUrl）
4. 再创建课件记录：`POST /api/v1/resources`（含 fileUrl + 元数据）
5. 成功 → toast + 关闭弹窗 + 刷新列表
6. 失败 → 保留弹窗 + 错误提示

- 下载权限：公开课件所有教师可下载；私有课件仅上传者本人可下载
- 下载触发时计数 +1（异步更新）

#### 4.3.3 编辑课件

- 仅可编辑自己上传的课件
- 弹窗编辑：课件名称、科目、年级、类型、共享范围可修改；文件本身不可替换（如需更换，删除后重新上传）
- 共享范围变更：公开→私有（瞬间对其他教师不可见），私有→公开（瞬间对全体教师可见）

#### 4.3.4 删除课件

- 仅可删除自己上传的课件
- 二次确认："确认删除课件「{课件名称}」？删除后将无法恢复。"
- 逻辑删除，文件物理保留

## 6. 全局业务规则

### 6.1 教师数据隔离规则

| 规则编号 | 规则 | 适用范围 |
|:--:|------|---------|
| TR01 | `teacher_id = 当前教师` 过滤排课 | N09.1, N09.4 |
| TR02 | `teacher_id = 当前教师` 过滤作业 | N09.2 |
| TR03 | `uploader_id = 当前教师 OR is_public = 1` 过滤课件 | N09.3 |
| TR04 | 编辑/删除操作前校验 `teacher_id` 或 `uploader_id` 匹配 | N09.2, N09.3 |
| TR05 | 班级下拉选项限定为 `teacher_id = 当前教师` 的班级 | N09.2, N09.4 |
| TR06 | 课程下拉选项限定为教师所教科目的课程 | N09.2, N09.4 |

### 6.2 "今日"判定规则

- "今日"以**服务器时间**为准（`LocalDate.now()`）
- 前端不传日期参数给今日相关 API
- 避免客户端时间被篡改导致数据错乱

### 6.3 教师身份获取

- 后端从 JWT Token 中获取当前登录用户 ID
- 通过 `sys_user` 表关联 `edu_teacher` 表获取 `teacher_id`
- 教师角色通过 `@PreAuthorize("@ss.hasRole('teacher')")` 控制

### 6.4 菜单可见性

- 教师端 4 项菜单仅对角色为「教师」的用户可见
- 校长/运营主管的左侧菜单不包含 N09
- 教师登录后默认首页为 N09.1 教师工作台
- 教师不可访问 N01-N08 的菜单（除共享权限外）

### 6.5 小程序端与 PC 端的关系

- 教师签到操作建议在小程序端完成（拍照/扫码签到更便捷）
- PC 端「可签到」按钮可打开签到弹窗（PC 兼容模式），或展示提示引导使用小程序
- 作业布置、课件上传功能 PC 端和小程序端均可使用

#### 7.1.1 GET `/api/v1/teacher/dashboard/statistics`

响应示例：
```json
{
  "code": 200,
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `scheduleId` | Long | 排课记录 ID |

| `endTime` | String | 结束时间 HH:mm |
| `courseName` | String | 课程名称 |
| `className` | String | 班级名称 |
| `classroomName` | String | 教室名称 |

| `courseStatus` | String | 课程状态：`NOT_STARTED` / `IN_PROGRESS` / `FINISHED` |
| `attendanceStatus` | String | 签到状态：`NOT_STARTED`(未开始) / `UNCHECKED`(未签到) / `PARTIAL`(部分签到) / `COMPLETED`(全部签到) |

## 9. 与主模块的关系说明

### 9.1 关系总览

```
主模块（运营/校长视角）              教师端（教师视角）
─────────────────────────          ─────────────────
N01 工作台（全局仪表盘）     →     N09.1 教师工作台（个人仪表盘）[NEW]
N05.1 作业管理（全部作业）   →     N09.2 课后作业（自己的作业） [VIEW]
N03.7 课件管理（全部课件）   →     N09.3 课件共享（公开 + 自有）[VIEW]
N03.1 课程表（全部排课）     →     N09.4 我的课表（自己的课表） [VIEW]
```

### 9.2 后端复用策略

| 策略 | 适用模块 | 说明 |
|------|---------|------|
| **同一接口 + Service 层过滤** | N09.2, N09.3 | Controller 同一端点，Service 层根据当前角色自动过滤数据范围 |
| **独立端点 + 复用 Service** | N09.4 | 新增 `teacher/` 前缀端点，内部调用同一 Service 方法 |
| **全新模块** | N09.1 | 独立的 `edu-module-teacher-dashboard` 模块，跨模块聚合数据 |

### 9.3 前端复用策略

| 策略 | 适用页面 | 说明 |
|------|---------|------|
| **全新页面** | N09.1 | 教师工作台为全新页面，采用 N01 工作台的设计模式 |
| **路由重定向 + 过滤** | N09.2, N09.3, N09.4 | 复用主模块的页面组件，通过路由参数/Store 状态区分教师视图，控制数据范围和操作权限 |
| **组件复用** | N09.2 布置作业弹窗, N09.3 上传弹窗 | 直接复用 N05.1 的作业表单组件、N03.7 的课件上传组件 |

### 9.4 数据一致性保障

- 教师端和主模块共用相同的数据库表，数据的实时一致性天然保证
- 教师端不创建冗余数据表（教师工作台统计为实时聚合查询，不做数据镜像）
- 缓存策略：教师端不独立设置缓存，复用主模块的 Redis 缓存层
