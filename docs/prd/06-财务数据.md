# N06 财务数据

> **模块编码**：N06 | **菜单名**：财务数据 | **优先级**：P0
> **访问角色**：运营主管 / 校长
> **后端模块**：`edu-module-enrollment` + `edu-module-tuition` + `edu-module-payroll` [NEW]
> **前端路由**：`/finance/tuition`、`/finance/teacher-payroll`、`/finance/teaching-stats`
>
> 本模块是"报名 → 收费 → 课时入账 → 消课 → 课酬"资金全链路的承载模块，合并原 v2.0 中 M6 报名管理 + M7 收银管理，并新增消课课酬与授课统计两个子页。

---

## 1. 模块概述

### 1.1 模块定位

N06 财务数据是机构资金流的中枢模块，覆盖从招生报名、收费确认、退费审批、赠送课时、财务对账，到教师课酬计算与授课统计的完整财务闭环。三个子页各司其职：

| 子页 | 路由 | 定位 | 数据来源 |
|:----:|------|------|------|
| N06.1 款项管理 | `/finance/tuition` | 报名→收费→退费→赠送→对账的资金操作面 | N02 学员 + N03 课程/班级 |
| N06.2 消课课酬 | `/finance/teacher-payroll` | 教师课酬自动计算、确认与发放 | N07 考勤消课 + 教师档案 |
| N06.3 授课统计 | `/finance/teaching-stats` | 教师授课课时与学评教排名只读聚合 | N03 排课 + N07 考勤 + N05 学评教 |

### 1.2 模块依赖关系

```
N02 (学员管理) ──→ N06.1 报名时选择学员
N03 (教务系统) ──→ N06.1 报名时选择课程/班级，退费/赠送关联课程
N07 (考勤管理) ──→ N06.2 消课数据来自考勤签到
                ──→ N06.3 授课课时统计来自排课+考勤
N05 (家校沟通) ──→ N06.3 学评教排名数据
N01 (工作台)   ←── N06 营收统计卡片
N02 (学员管理) ←── N06.1 收费后写入课时余额
```

### 1.3 角色权限

| 功能 | 校长 | 运营主管 | 教师 | 家长 |
|------|:--:|:--:|:--:|:--:|
| N06.1 款项管理（全部操作） | ✅ | ✅ | ❌ | ❌ |
| N06.1 退费审批 | ✅ | ❌ | ❌ | ❌ |
| N06.2 消课课酬查看 | ✅ | ✅ | ❌ | ❌ |

#### 2.2.3 课程-班级联动逻辑

```
用户选择课程 ──→ 触发联动：
  ├── 1. 该行的金额自动填充为所选课程的单价
  └── 2. 班级下拉选项自动过滤为该课程关联的班级列表
         └── 班级下拉框显示格式：「班级名称（X/Y）」← X=已报人数，Y=最大人数
                  ├── 有剩余名额：正常显示
                  ├── 已满：选项置灰 + 标签"[已满]"
                  └── 若班级已满，用户仍可选择（允许超额报名，由主管判断）
```

#### 2.2.4 金额默认逻辑

| 场景 | 金额默认值 | 是否可修改 |
|------|-----------|:--:|
| 仅选课程 | 课程单价 | ✅ |
| 选课程 + 选班级 | 班级独立定价（如有）→ 课程单价 | ✅ |
| 手动修改后 | 保留手动值 | ✅ |

金额校验：最小 0.01 元，精度 2 位小数，提交时所有行金额之和 > 0。

#### 2.2.5 提交流程

```
点击「提交报名」
  ├── 前端校验：学生已选 + 报名日期有效 + 明细至少1行 + 每行课程已选 + 金额>0 + 无重复课程+班级
  ├── 提交按钮 loading
  ├── POST /api/v1/enrollments/batch
  │   ├── 后端校验：学生存在 / 课程上架 / 班级正常 / 经手人存在 / 金额有效
  │   ├── 创建 enrollment_record（状态=已报名）
  │   └── 调用 tuition Service 创建待收费条目
  ├── 成功：Toast "报名提交成功，已生成待收费记录" → 切换到收费管理 Tab
  └── 失败：保留表单 + 显示错误信息
```

#### 2.2.6 状态处理

| 状态 | 处理方式 |
|------|----------|
| 加载中 | 页面顶部骨架屏（基本信息区灰色条块 + 表格骨架行 3 行），禁用提交按钮 |
| 学生下拉为空 | 显示"暂无学生数据"，提示"请先在学员管理中录入学生信息" |
| 课程下拉为空 | 显示"暂无课程数据" |
| 班级下拉为空 | 显示"该课程暂无关联班级，可跳过班级选择直接报名课程" |
| 班级已满 | 选项置灰 + "[已满]"，仍可选择但显示橙色警告 |
| 提交 loading | 按钮显示 spinner + "提交中..."，所有输入控件禁用 |
| 提交失败 | 保留表单数据，el-alert（红色）展示错误，不自动消失 |
| 网络超时 | 提示"网络请求超时，请重试"，保留表单数据 |

#### 2.2.7 业务规则

| 编号 | 规则 | 说明 |
|:--:|------|------|
| R1 | 学生校验 | 报名学生必须存在于 N02 学员管理中 |
| R2 | 课程校验 | 报名课程必须处于「上架」状态 |
| R3 | 班级校验 | 选择班级时，班级必须状态正常；班级已满给出警告但不阻止 |
| R4 | 金额校验 | 金额必须 > 0，不支持 0 元或负金额 |
| R5 | 经手人校验 | 经手人必须是系统有效用户 |
| R6 | 重复检查 | 同一学生对同一课程+班级组合，已存在未取消/未退费报名时，前端警告+后端拒绝 |
| R7 | 日期校验 | 报名日期不能是未来日期 |
| R8 | 批量提交 | 同一学生可在一次提交中报多门课程/班级 |

**表单字段**：

|------|------|:--:|------|

| 费用类型 | 下拉单选 | ✅ | 默认继承报名记录的费用类型，可修改 |
| 实缴金额 | 数字输入 | ✅ | `0 < 实缴金额 ≤ 未缴金额` |
| 备注 | 文本域 | ❌ | 最多 200 字符 |

**课时入账预览**：
- 入账课时数 = floor(实缴金额 / 课程单价)
- 课程单价未设置 → 显示"本次收费不涉及课时入账"
- 实缴金额 < 课程单价 → 警告"本次缴费金额不足以覆盖 1 课时，将不触发课时入账"

**确认收费交互**：
- 打开时自动填充未缴金额为实缴金额（一键全额收费）
- 修改实缴金额 → 实时更新课时入账预览
- 确认收费 → 调用 API → 成功 → toast + 关闭弹窗 + 刷新列表
- 生成收费编号 `T` + YYYYMMDD + 4位流水号

### 3.6 教师课酬单价配置

> 课酬单价采用「教师默认价 + 班级可覆盖」模式。大部分情况下无需额外配置，仅特殊班级需要手动覆盖。

#### 3.6.1 课酬单价规则

```
课酬单价 = 班级级单价（如有覆盖） ? 班级级单价 : 教师默认课酬
```

| 配置位置 | 说明 | 使用场景 |
|------|------|------|
| **教师档案 → 默认课酬** | 每个教师设置一个默认课酬单价 | 90% 的情况直接用这个 |
| **班级 → 课酬单价覆盖** | 班级可手动设置课酬单价覆盖默认值 | 同一个教师教不同班级、不同价 |

#### 3.6.2 教师档案 — 默认课酬

在 N03 教务系统 → 教师管理 → 编辑教师时增加字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `default_pay_per_lesson` | DECIMAL(10,2) | ✅ | 默认课酬单价（元/节），必须 > 0 |

#### 3.6.3 班级 — 课酬单价覆盖

在 N03 教务系统 → 班级管理 → 编辑班级时增加字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `pay_rate_override` | DECIMAL(10,2) | ❌ | 课酬单价覆盖（元/节），不填则用教师默认价 |

**交互**：
- 创建班级时不填 → 自动用教师的默认课酬
- 填写了 → 覆盖默认课酬
- 编辑班级时可修改/清空覆盖价

### 3.7 业务规则

| 编号 | 规则 | 说明 |
|:--:|------|------|
| PR1 | 消课数定义 | 消课数 = 该月该教师该课程所有签到记录中状态为"到校"+"迟到"的人次总和 |
| PR2 | 数据来源 | 消课数据来源为 N07 考勤管理，由系统自动聚合，不可手动修改 |
| PR3 | 代课课酬 | 代课教师的消课计入代课教师（即实际签到上课的教师），课酬归代课教师 |
| PR4 | 每月自动计算 | 每月 1 号凌晨系统自动计算上月课酬，生成草稿状态记录 |
| PR5 | 手动触发 | 提供「重新计算」按钮（工具栏），对选中的月份/教师重新拉取考勤数据计算 |
| PR6 | 确认锁定 | 确认后消课数和单节课酬锁定，不可修改；取消确认后恢复草稿 |

| PR9 | 无消课记录 | 该月该教师该课程无签到记录 → 不生成课酬记录（不出现 0 消课 0 薪酬的行） |

## 5. 全局业务规则

### 5.1 报名 → 收费 → 课时入账 完整流程

```
1. 运营主管在 N06.1「报名录入」Tab 录入报名信息
   → 选择学生 + 课程/班级 + 应缴金额 + 经手人
   → 生成 enrollment_record（状态=已报名，收费状态=待收费）
   → 调用 tuition Service 创建待收费条目

2. 运营主管在 N06.1「收费管理」Tab 确认收费
   → 选择支付方式 + 实缴金额（支持部分收费）
   → 系统生成收费记录 + 收费编号（T + 日期 + 流水号）
   → 回写 enrollment_record 收费状态：
      实缴金额 < 应缴金额 → 部分收费
      实缴金额 = 应缴金额 → 已收费
   → 如有课程单价：入账课时数 = floor(实缴金额 / 课程单价)
      写入 N02 学员课时明细（类型=报名获得，关联收费编号）
   → 如无课程单价：不触发课时入账

3. 后续可对同一报名记录追加收费（分期场景）
   → 每次收费独立生成收费编号
   → 每次独立计算课时入账
   → 当累计实缴金额 = 应缴金额时，报名记录状态变更为「已收费」
```

### 5.2 退费审批流程

```
运营主管发起退费申请
  ├── 退费金额 ≤ 审批阈值（默认500元）
  │   └── 直接通过，状态=已完成，课时扣回立即执行
  └── 退费金额 > 审批阈值
      ├── 状态=待审批，进入审批队列
      ├── 校长审批通过 → 状态=已通过 → 执行课时扣回
      └── 校长驳回 → 状态=已驳回（终态），需重新发起申请
```

审批阈值配置项：`tuition.refund.approval_threshold`，通过 N08 系统配置管理。

### 5.3 收费类型与课时规则

| 费用类型 | 编码 | 是否涉及课时入账 | 说明 |
|------|------|:--:|------|
| 报名费 | `REGISTRATION` | ❌ | 报名时一次性收取 |
| 课时费 | `TUITION` | ✅ | 按课程单价计算课时入账 |
| 教材费 | `MATERIAL` | ❌ | 教材/资料费 |
| 其他费用 | `OTHER` | ❌ | 杂费、活动费等 |

**课时计算规则**：
- 入账课时 = floor(实缴金额 / 课程单价)，向下取整
- 扣回课时 = ceil(退费金额 / 课程单价)，向上取整
- 实缴金额 < 课程单价 → 不触发课时入账，前端警告

### 5.4 编号规则

| 编号前缀 | 格式 | 示例 | 说明 |
|------|------|------|------|
| `T` | `T` + YYYYMMDD + 4位流水 | `T202607130001` | 收费编号（Tuition） |
| `R` | `R` + YYYYMMDD + 4位流水 | `R202607130001` | 退费编号（Refund） |
| `G` | `G` + YYYYMMDD + 4位流水 | `G202607130001` | 赠送编号（Gift） |

流水号按业务类型独立编号，每日从 0001 开始，后端全局唯一生成。

### 5.5 部分收费规则

| 规则 | 说明 |
|------|------|
| 分期限额 | 单次最低实缴金额 1 元 |
| 次数不限制 | 同一报名记录可多次收费，直到缴清 |
| 课时入账 | 每次收费独立计算课时入账 |
| 课时不足 1 时 | 实缴金额 < 课程单价 → 不触发课时入账（费用照收，课时不计） |
| 状态流转 | 累计已缴 < 应缴 → 部分收费；累计已缴 = 应缴 → 已收费 |

### 5.6 退费课时扣回计算

扣回课时数 = `ceil(退费金额 / 课程单价)`，向上取整。扣回后剩余课时 < 0 时前端橙色警告，人工确认后仍可执行。

### 5.7 消课课酬自动计算

每月 1 号凌晨自动计算上月课酬：
- 消课数 = 该月该教师该课程签到"到校"+"迟到"人次（来源 N07）
- 代课教师的消课计入代课教师（非原排课教师）
- 课酬单价取该月有效的 per-teacher-per-course 配置
- 无配置则单节课酬 = 0，前端标红提示
- 无消课记录则不生成课酬记录

## 9. 异常边界

### 9.1 报名录入异常

| 场景 | 处理方式 |
|------|------|
| 学生不存在 | 返回 400："所选学生不存在" |
| 课程不存在或已下架 | 返回 400："课程「{name}」不存在或已下架" |
| 班级不存在 | 返回 400："班级「{name}」不存在或已停用" |
| 同课程同班级重复报名 | 返回 400："该学生已报名此课程+班级组合，请勿重复报名" |
| 待收费条目创建失败 | 事务回滚，报名记录不创建，返回 500 |
| 编辑已收费的报名 | 返回 400："已收费报名不可编辑" |
| 取消已收费的报名 | 返回 400："已收费报名不可取消，请通过收银管理处理退费" |

### 9.2 收费与退费异常

| 场景 | 处理方式 |
|------|------|
| 并发收费（两人同时确认同一报名记录） | 后端乐观锁/数据库行锁，后提交者提示"该报名记录已被他人修改，请刷新后重试" |
| 退费金额超过可退上限 | 前端「可退上限」控制，后端二次校验，返回 400 |
| 同一退费申请被多人同时审批 | 后端乐观锁，先成功者胜出，提示"该退费申请已被处理" |
| 退费审批人已离职/停用 | 审批列表仍显示待审批，其他有审批权限的用户可审批 |
| 审批阈值配置为负数 | 后端校验，阈值最小为 0（所有退费均需审批），拒绝负值 |
| 课程未设置单价 | 收费时不触发课时入账；退费时不触发课时扣回 |
| 退费后课时余额为负 | 前端橙色警告，人工确认后仍可执行 |
| 实缴金额 ≤ 0 或超过 ¥999,999.99 | 前端拦截 + 后端二次校验 |

### 9.3 消课课酬异常 [NEW]

| 场景 | 处理方式 |
|------|------|
| 教师未配置课酬单价 | 单节课酬 = 0，记录正常生成，前端标红"未配置课酬单价"，可确认但不触发实际发放 |
| 该月该教师该课程无消课 | 不生成课酬记录（不出现 0 消课 0 薪酬的行） |
| 每月 1 号自动计算任务失败 | 记录 ERROR 日志 + 告警通知管理员，支持手动"重新计算"补救 |
| 已确认记录被取消确认后再确认 | 重新锁定当时的消课数和单价，不重新拉取（防止数据变化导致不一致） |
| 课酬单价配置有效期重叠 | 后端唯一约束拒绝，返回 400："该教师在此课程下已有重叠的有效期配置" |
| 手动重新计算覆盖已确认记录 | 仅覆盖草稿状态记录，已确认/已发放记录不参与重新计算 |

### 9.4 数据一致性异常

| 场景 | 处理方式 |
|------|------|
| 报名记录已被删除 | 待收费列表不展示；如收费记录已关联，仍可查看但标注"原报名记录已删除" |
| 原收费记录已被删除 | 退费记录不可创建；已有退费进入只读状态，标注"原收费记录已删除" |
| 学生已停课/流失 | 仍可收费（历史缴费）；仍可退费（余额退还）；退费课时扣回不足需人工确认 |
| M6→M7 创建待收费条目超时 | M6 事务回滚，报名记录不创建，前端提示"报名提交失败，请重试" |
| M7→M6 回调更新收费状态失败 | M7 侧重试机制（3 次，指数退避）；最终一致性保证 |
