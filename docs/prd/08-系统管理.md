# N08 系统管理

> **模块定位**：所有业务模块的前置底座，提供用户认证、权限控制、系统配置和审计日志能力。
> **优先级**：P0（MVP 必须，Phase 0 最先完成）
> **路由前缀**：`/system`
> **后端模块**：`edu-module-system`
> **访问角色**：校长（PRINCIPAL）——运营主管不可见
> **菜单位置**：左侧菜单最底部，仅校长可见

### 2.5 新增/编辑弹窗

#### 弹窗规格

- 宽度：560px
- 标题："新增用户" 或 "编辑用户"

#### 表单字段

| 字段 | 类型 | 必填 | 新增时 | 编辑时 | 校验规则 |
|------|------|:--:|:--:|:--:|------|
| 用户名 | 文本 | 是 | 显示 | 只读 | 2-20字符，字母数字下划线，失焦异步校验唯一性 |
| 密码 | 密码 | 是(新增) | 显示 | **不显示** | 新增必填6-20字符；编辑时无此字段（另行重置） |
| 姓名 | 文本 | 是 | 显示 | 显示 | 1-20字符。失焦时检测重名：如已有同名用户，蓝色提示"已有同名用户，建议在姓名后加数字区分，如「{姓名}01」"，不阻止提交 |
| 手机号 | 文本 | 是 | 显示 | 显示 | 11位数字格式。失焦异步校验唯一性（编辑时排除自身），如已存在 → 红色提示"该手机号已被使用" + 不可提交 |
| 性别 | 单选组 | 否 | 显示 | 显示 | 男 / 女 / 未知 |
| 角色 | 多选下拉 | 否 | 显示 | 显示 | 调用 `GET /api/v1/system/role/all` 加载选项，支持多选+搜索 |
| 备注 | 文本域 | 否 | 显示 | 显示 | 最多500字符，右下角计数器 |

#### 唯一性校验

| 字段 | 校验时机 | 校验方式 | 类型 |
|------|------|------|:--:|
| 用户名 | 失焦 | 调后端查询是否已存在（编辑时排除自身） | 硬阻断 |
| 手机号 | 失焦 | 调后端查询是否已存在（编辑时排除自身），重复则提示"该手机号已被使用" | 硬阻断 |
| 姓名 | 失焦 | 调后端查询是否已存在同名用户 | 软提示 |

**硬阻断**：校验失败 → 红色错误提示，不可提交
**软提示**：校验到重名 → 蓝色信息提示"已有同名用户，建议在姓名后加数字区分，如「{姓名}01」"，不阻止提交

校验中 → 输入框右侧 loading 图标；校验通过 → 绿色勾；校验失败 → 红色叉 + 错误提示

#### 交互

| 操作 | 行为 |
|------|------|
| 打开（新增） | 空表单，默认性别"未知" |
| 打开（编辑） | 调用 `GET /api/v1/system/user/{id}` → 填充表单（密码不显示，角色回填） |
| 确认 | 前端校验 → 提交API → 成功 → toast + 关闭弹窗 + 刷新列表 |
| 取消 | 有修改 → 确认"放弃修改？"；无修改 → 直接关闭 |

#### 对应API

| 操作 | API |
|------|------|
| 新增 | `POST /api/v1/system/user` |
| 编辑 | `PUT /api/v1/system/user/{id}` |
| 详情 | `GET /api/v1/system/user/{id}` |
| 角色选项 | `GET /api/v1/system/role/all` |
| 状态切换 | `PUT /api/v1/system/user/{id}/status` |
| 删除 | `DELETE /api/v1/system/user/{ids}` |
| 重置密码 | `PUT /api/v1/system/user/{id}/password` |

### 2.7 导入

#### 密码策略

导入模板**不含密码列**。导入时系统为每个用户自动生成8位随机密码（大小写字母+数字）。

#### 导入流程

1. 点击"下载模板"→ `GET /api/v1/system/user/template` → 浏览器下载Excel
2. 点击"导入"→ 打开导入弹窗
3. 上传文件 → 文件格式校验（仅允许 `.xlsx` `.xls`，最大10MB）→ 调 `POST /api/v1/system/user/import`
4. 返回结果 → 弹窗展示导入结果 → 关闭弹窗 → 刷新列表

#### 导入弹窗

- 上传区域：拖拽或点击上传
- 下载模板链接
- 上传中：进度条

> 本文档定义所有配置项的键名、用途和使用方。

### 5.1 设计决策

| 决策 | 结论 |
|------|------|
| 管理方式 | `application.yml` 硬编码，无管理页面 |

| 为何不做管理页面 | MVP 阶段配置项少且变动频率极低，管理页面投入产出比低 |

- `application-dev.yml` — 开发环境
- `application-prod.yml` — 生产环境

### 5.4 后端读取方式

后端通过 `@ConfigurationProperties` 绑定：

```java
@ConfigurationProperties(prefix = "institution")
public class InstitutionConfig {
    private String name;
    private String phone;
    private String copyright;
}

@ConfigurationProperties(prefix = "wechat")
public class WechatConfig {
    private String appId;
    private String appSecret;
}
```

前端需要的配置（机构名称、电话）通过以下方式获取：
- 登录接口 `POST /api/v1/auth/login` 返回时可附带 `institutionName`
- 或新增 `GET /api/v1/public/config` 公开接口，返回前端需要的非敏感配置

### 5.5 注意事项

- `wechat.app-secret` 为敏感信息，不得在日志、前端响应、错误信息中暴露
- 配置变更需重启服务，MVP 阶段不提供热更新
- 新增配置项时同步更新本文档

   - 输入框：请手动输入"确认清空"以继续
   - "取消"按钮 + "确认清空"按钮（红色，disabled 直到输入正确文字）
3. 输入"确认清空"→ 确认按钮可用 → 点击 → 调用 `DELETE /api/v1/system/log/operlog/clean`

## 7. 登录认证

> 路由：`/login` | 权限码：无（公共接口）

### 7.1 登录方式全景

| 角色 | PC端 | 小程序端 |
|------|:----:|:--------:|
| 校长/运营主管 | 账号密码 | — |
| 教师 | 账号密码 | 微信静默登录 |
| 家长 | — | 微信静默登录 |

### 7.2 PC端登录流程

#### 页面布局

居中卡片式。左侧机构Logo + 名称，右侧登录表单。

```
┌─────────────────────────────────────────┐
│                                         │
│   ┌───────────────────────────────┐     │
│   │  Logo                        │     │
│   │  新艺智源管理平台              │     │
│   │                              │     │
│   │  * 账号    [______________]  │     │
│   │  * 密码    [______________]  │     │
│   │  验证码    [____] [图片]      │     │
│   │  [ ] 记住我                   │     │
│   │  [      登 录      ]          │     │
│   └───────────────────────────────┘     │
└─────────────────────────────────────────┘
```

#### 元素规格

| 元素 | 类型 | 说明 |
|------|------|------|
| 账号 | 文本输入 | placeholder:"请输入手机号/姓名/用户名"，支持手机号、姓名、用户名任一方式登录 |
| 密码 | 密码输入 | placeholder:"请输入密码"，支持Enter提交 |
| 验证码 | 文本+图片 | 4位图片验证码，点击图片刷新；**MVP阶段后端未实现，前端预留位置隐藏即可** |
| 记住我 | checkbox | 勾选 → token 存 localStorage；不勾选 → sessionStorage |
| 登录按钮 | 按钮 | 宽度与输入框一致，loading态显示"登录中…" |

#### 提交流程

1. 前端校验：账号非空 + 密码非空
2. 调用 `POST /api/v1/auth/login`，传 `{ account, password }`，后端按手机号 → 姓名 → 用户名优先级匹配
3. 成功 → 存token → 跳转 `/dashboard`（或跳回 `redirect` 参数目标页）
4. 失败 → 密码框清空 + 验证码刷新 + 显示错误信息

#### 错误信息映射

| 后端返回 | 前端提示 |
|----------|----------|
| 401 账号或密码错误 | "账号或密码错误" |
| 401 账号已停用 | "账号已被停用，请联系管理员" |
| 其他 | "登录失败，请重试" |

#### 状态处理

| 状态 | 表现 |
|------|------|
| 正常 | 显示登录表单 |
| 提交中 | 按钮loading，"登录中…"，输入框禁用 |
| 失败 | 密码清空，红色错误提示在密码框下方 |
| 未登录访问 | 路由守卫 → 自动跳转 `/login`，登录后到首页 |
| Token过期 | 接口返回401 → 清除token → 跳转 `/login` + 提示"登录已过期，请重新登录" |
| 已登录访问 | 路由守卫 → 直接跳转 `/dashboard` |

#### 对应API

| 接口 | 说明 |
|------|------|
| `POST /api/v1/auth/login` | 登录，入参 `{ account, password }`（account 支持手机号/姓名/用户名），返回 `{ accessToken, refreshToken, userId, username, realName, avatar, permissions, roles }` |

### 7.3 小程序微信登录流程

> 详细设计见 `docs/prd/10-小程序功能设计.md` 第2章

**流程概要**：

1. 小程序端调用 `wx.login()` 获取临时 `code`
2. 小程序端将 `code` 发送到后端 `POST /api/v1/auth/wechat-login`
3. 后端调用微信 `jscode2session` 获取 `openid` 和 `session_key`
4. 后端根据 `openid` 查找关联的 `sys_user`（通过 `wx_openid` 字段）
   - 若找到关联用户 → 生成JWT → 返回登录成功
   - 若未找到 → 返回"未绑定"状态 → 前端引导用户绑定手机号
5. 手机号绑定：用户授权微信手机号 → 前端调 `POST /api/v1/auth/wechat-bind` → 后端解密手机号 → 关联或创建 `sys_user` → 完成登录

### 7.4 JWT Token 机制

| 属性 | 说明 |
|------|------|
| Token类型 | JWT（accessToken + refreshToken 双token） |
| accessToken 有效期 | 2小时 |
| refreshToken 有效期 | 7天 |
| Token存储 | PC端：localStorage（记住我）或 sessionStorage（不记住）；小程序端：本地缓存 |
| 刷新机制 | accessToken 过期 → 前端用 refreshToken 调 `POST /api/v1/auth/refresh` 获取新token |
| 请求携带 | `Authorization: Bearer {accessToken}` |
| Token内容 | `{ userId, username, permissions[], roles[] }` |

### 7.5 登录失败限制（P1 待实现）

| 属性 | 说明 |
|------|------|
| 失败次数上限 | `security.login-max-retry`（默认5次） |
| 锁定时长 | `security.lock-duration`（默认15分钟） |
| 锁定维度 | 按账号（username） |
| 锁定表现 | 该账号在锁定时长内无法登录，提示"账号已被锁定，请 {N} 分钟后重试" |
| 计数重置 | 成功登录后重置失败计数 |
| 记录方式 | 登录失败事件纳入 `sys_oper_log`（`businessType` = LOGIN） |

## 9. 业务规则

### 9.1 用户管理规则

| 规则 | 说明 |
|------|------|
| 自我保护 | 当前登录用户不能停用或删除自己 |
| 超管保护 | `userId=1` 的超级管理员不能停用或删除 |
| 用户名唯一 | 全系统唯一，新增/编辑时异步校验 |
| 手机号唯一 | 全系统唯一（编辑时排除自身），新增/编辑时异步校验 |
| 姓名软校验 | 重名仅提示不阻止，建议加数字区分 |
| 密码规则 | 新增时必填6-20字符；编辑时通过独立"修改密码"功能操作 |
| 密码加密 | BCrypt 加密存储（`password_hash`），不可逆 |
| 手机号脱敏 | 列表展示 `138****5678` 格式 |
| 导入密码 | 系统自动生成8位随机密码（大小写字母+数字），不含密码列 |
| 用户状态流转 | 正常 ↔ 停用（双向切换，二次确认） |
| 默认密码 | `security.default-password`，默认 `123456` |

### 9.2 角色管理规则

| 规则 | 说明 |
|------|------|
| 超管角色保护 | `code=admin` 的角色不可删除 |
| 角色编码唯一 | 全系统唯一，字母开头，仅字母数字下划线 |
| 关联用户保护 | 角色下有用户时，删除弹窗显示用户数，确认后级联解除关联 |
| 停用影响 | 停用角色后，该角色下用户立即失去对应权限 |
| 菜单分配 | 全量替换模式（前端收集全部勾选ID传给后端） |
| 用户分配 | 全量替换模式（前端收集右侧全部用户ID传给后端） |

### 9.3 菜单管理规则

| 规则 | 说明 |
|------|------|
| 删除级联 | 删除父节点时，所有子孙节点一并删除，并清除 role-menu 关联 |
| 按钮无子级 | type=F（按钮）的行隐藏"新增子级"按钮 |
| 目录可含子级 | 目录下可有目录或菜单；菜单下仅可有按钮 |
| 类型不可变 | 编辑时菜单类型锁定（创建时即固定） |
| 隐藏菜单 | `visible=false` 的菜单前端不显示，但权限码仍生效 |

### 9.4 操作日志规则

| 规则 | 说明 |
|------|------|
| 自动记录 | 新增/修改/删除/导入/导出/授权/密码重置等操作通过AOP自动记录 |
| 登录事件 | 登录成功/失败统一记录到 `sys_oper_log`，业务类型=LOGIN |
| 密码脱敏 | 登录日志的请求参数中密码字段替换为 `****` |
| 清空保护 | 清空全部需输入"确认清空"文字验证 |
| 不可恢复 | 删除和清空操作不可恢复 |

### 9.5 跨模块关联规则

| 关联 | 方式 |
|------|------|
| 教师 ↔ sys_user | `sys_user.mobile` ↔ 教师档案表 `mobile` |
| 家长 ↔ sys_user | `sys_user.mobile` ↔ 学生档案中家长手机号 |
| 家长账号创建 | 录入学生时自动检查/创建，`wx_openid` 首次小程序授权时绑定 |
| 后续模块菜单 | 通过SQL预制脚本批量插入 `sys_menu` |

## 13. 异常边界

### 13.1 加载态

| 场景 | 表现 |
|------|------|
| 列表首次加载 | 表格骨架屏（灰色条块动画） |
| 菜单树加载 | 树形表格骨架屏（灰条 + 折叠箭头占位） |
| 编辑弹窗加载 | 弹窗内骨架屏 / spinner |
| 详情抽屉加载 | 抽屉内骨架屏 |
| 权限树加载 | 树组件骨架屏 |
| 按钮提交中 | 按钮 loading + 文案"保存中…"/"登录中…" |

### 13.2 空状态

| 场景 | 表现 |
|------|------|
| 用户列表为空 | 空状态插图 + "暂无用户数据" |
| 角色列表为空 | 空状态插图 + "暂无角色数据" |
| 菜单树为空 | 空状态插图 + "暂无菜单数据，点击「新增」创建根级菜单" |
| 操作日志为空 | 空状态插图 + "暂无操作日志" |
| 搜索无结果 | "未找到匹配的{实体名}"+ "清空筛选"按钮 |

### 13.3 错误态

| 场景 | 表现 |
|------|------|
| 列表加载失败 | "数据加载失败" + "重试"按钮 |
| 详情加载失败 | Dialog/抽屉内错误提示 + "重试"按钮 |
| 提交失败 | 保留弹窗/抽屉 + 红色错误提示 |
| 网络错误 | 全局 toast "网络异常，请重试" |
| 401未认证 | 清除token → 跳转 `/login` + "登录已过期，请重新登录" |
| 403无权限 | 页面显示 403 禁止访问提示 |
| 404不存在 | 页面显示 404 未找到提示 |
| 唯一性校验失败 | 输入框红色边框 + 具体错误文案（如"用户名已存在"） |
| 唯一性校验超时 | 输入框恢复默认状态（不阻断提交，后端二次校验兜底） |

### 13.4 边界条件

| 场景 | 处理 |
|------|------|
| 删除超级管理员 | 前端隐藏删除按钮 + 后端鉴权拒绝 |
| 删除admin角色 | 前端隐藏删除按钮 + 后端鉴权拒绝 |
| 当前用户删除自己 | 前端隐藏删除按钮 |
| 停用当前用户 | 前端隐藏停用按钮 |
| 删除有子级的菜单 | 二次确认告知子级数量 + 后端级联删除 |
| 删除有关联用户的角色 | 二次确认告知用户数量 + 后端级联解除关联 |
| 导入文件格式错误 | 上传校验，仅允许 `.xlsx` `.xls`，最大10MB |
| 导入数据行错误 | 逐行校验，失败行列出原因，成功行正常入库 |
| 清空操作日志 | 输入"确认清空"文字验证，防止误操作 |
| 并发编辑 | 不做乐观锁，以后提交为准覆盖（MVP阶段简化处理） |
| Token即将过期 | 前端在请求拦截器中检测，过期前5分钟静默刷新 |

### 13.5 表单通用规则

| 规则 | 说明 |
|------|------|
| 必填标记 | 必填字段 label 前红色 `*` |
| 校验时机 | 失焦校验 + 提交前全量校验 |
| 唯一性校验 | 用户名、编码等字段失焦时异步校验，重复则提示已存在 |
| 提交反馈 | 成功 → 关闭弹窗 + 刷新列表 + 成功提示；失败 → 保留弹窗 + 错误提示 |
| 重复提交 | 提交按钮点击后 loading，禁止重复点击 |
| 取消确认 | 表单有修改时点取消 → 弹窗确认"是否放弃修改？" |
