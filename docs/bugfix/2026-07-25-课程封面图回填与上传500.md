# Bug 修复记录 — 课程封面图回填 + 文件上传 500

> 日期：2026-07-25  
> 触发：课程管理编辑时封面图不回填，且文件上传接口返回 500
> 更新：修复后前端仍无法显示图片 — 新增问题 3（Vite 代理缺失）

---

## 问题 1：编辑课程时封面图不回填

### 现象

新增课程时上传封面正常显示，但编辑已有课程时，`el-upload` 组件不显示已有封面图。

### 排查链路

1. 定位前端表单组件 → `CourseFormModal.vue:132-133`
2. 封面回填 URL 构造：
   ```javascript
   coverFileList.value = [{ name: c.coverImage, url: `/api/v1/files/${c.coverImage}` }];
   ```
3. 该 URL 命中 `FileController.download()` — **需要 JWT 认证** (`@PreAuthorize("isAuthenticated()")`)
4. `el-upload` 组件内部用 `<img>` 标签加载图片，浏览器原生请求**不带 `Authorization: Bearer` 头**
5. → 服务端返回 401，图片无法加载

**为什么上传预览正常？** `el-upload` 上传后用本地 blob URL 预览，不经过服务端。

### 修复

| 层 | 文件 | 改动 |
|----|------|------|
| 后端 | `edu-common/.../WebMvcConfig.java` | 新增 `addResourceHandlers` 映射 `/upload/**` → 文件系统上传目录 |
| 前端 | `CourseFormModal.vue` | URL 从 `/api/v1/files/` → `/upload/` |
| 前端 | `GiftDialog.vue` | 同上 + 旧数据兼容（`/api/v1/files/` → `/upload/` 自动替换） |

SecurityConfig 已提前配置了 `/upload/**` 安全扩展名 `permitAll()`，只需补 Spring MVC 资源映射即可。

## 问题 2：文件上传接口 500 Internal Server Error

### 现象

`POST /api/v1/files/upload` 始终返回 500，与文件大小、类型无关。

### 排查链路

#### 第一步：排除法

- 回退 `WebMvcConfig` 改动 → 仍然 500 → **排除我的改动导致**
- 不带 token → 401（认证正常）
- 不带 file 参数 → 500（`MissingServletRequestPartException` 被兜底 handler 捕获）
- 小文件 → 500（排除文件大小）
- 其他上传接口 `/api/v1/resources` → 也是 500 → **所有 MultipartFile 上传都挂**

#### 第二步：获取真实异常

修改 `GlobalExceptionHandler` 返回原始异常信息：

```
IOException: FileNotFoundException:
C:\Users\12859\AppData\Local\Temp\tomcat.8080...\work\Tomcat\localhost\ROOT\upload\202607\xxx.jpg
(系统找不到指定的路径。)
```

#### 第三步：根因定位

- `Paths.get("upload", "202607")` 使用**相对路径**
- 相对路径基于 `System.getProperty("user.dir")`
- 运行环境中 `user.dir` 被设为 **Tomcat 临时工作目录**（`C:\...\Temp\tomcat.8080...\work\...`）
- `Files.createDirectories()` 在临时目录下创建失败（或无权限）
- → `file.transferTo()` 抛出 `FileNotFoundException`

### 修复

`FileController.java` 添加 `@PostConstruct` 方法：

```java
@PostConstruct
private void resolveUploadPath() {
    Path absolute = Paths.get(uploadPath).toAbsolutePath().normalize();
    this.uploadPath = absolute.toString();
}
```

**关键教训：永远不要依赖 `user.dir`，生产环境中 JVM 工作目录不可控。**

## 问题 3：修复后前端仍无法显示图片

### 现象

上传 200，静态资源 `/upload/xxx.jpg` 直接 curl 也返回 200，但前端 `el-upload` 组件仍不显示封面图。

### 排查

`<img src="/upload/202607/xxx.jpg">` 在浏览器中请求的是 **`http://localhost:3000/upload/xxx.jpg`**（Vite 开发服务器端口）。

Vite proxy 配置只代理了 `/api-prefix/*`，**没有代理 `/upload/*`**。请求根本没到后端 → 404。

这是开发环境专属问题。生产环境前端和后端同域（Nginx 反代），不会有这个问题。

### 修复

`vite.config.js` 新增 `/upload` 代理：

```javascript
"/upload": {
  target: env.VITE_API_TARGET,
  changeOrigin: true
}
```

注意：`/upload` 不需要 `rewrite`（路径前后端一致），与 `/api-prefix` 不同。

**关键教训：开发环境代理 != 生产环境路由，每次新增后端 URL 前缀都要检查 Vite proxy 是否覆盖。**

## 排查方法论总结

| 步骤 | 做了什么 |
|------|----------|
| **1. 回溯数据流** | 从 UI → API → Controller → 文件系统，逐层验证 |
| **2. 排除法** | 回退改动确认无关；变换参数（无 token/无 file/小文件）缩小范围 |
| **3. 获取真实异常** | 临时改 `GlobalExceptionHandler` 暴露原始异常信息（最关键的步骤） |
| **4. 读异常消息** | `FileNotFoundException` + 意料之外的路径 → 立刻定位到 `Paths.get()` 相对路径问题 |
| **5. 找相同模式** | 检查是否还有其他地方也用 `transferTo()` — 发现 `EduResourceServiceImpl` 同样使用相对路径 |

### 核心原则

1. **先找根因，再写修复** — 不能凭猜测改代码
2. **拿到真实异常信息是排查的前提** — 不要被"服务器内部错误"这样的通用消息误导
3. **相对路径在服务端是陷阱** — 始终在启动时解析为绝对路径
4. **修改一个地方时，搜索同类模式** — 一起修，不留隐患
